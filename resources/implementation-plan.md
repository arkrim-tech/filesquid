# Implementation Plan: FileSquid

This document is the global, chronological roadmap for the software this repository delivers: **FileSquid** (one Rust backend, one API, the `ocfl`, `metadata`, `prov` and `c2pa` modules, desktop and multi-user server hosts, paid ciphertext-only backup and sync at `*.filesquid.tech`) and its white-label UI distributions, **ImageSquid** and later **Arkrim**. It synthesizes the [FileSquid vision](./product-vision.md), [prd.md](./prd.md), [srs.md](./srs.md), [architecture.md](./architecture.md), ADRs [001–040](./architecture/README.md) and the module SRS files. An ordered, release-grouped checklist of every global and module task is in [implementation-plan-checklist.md](./implementation-plan-checklist.md). Granular checklists live in each module:

Each module crate MUST still build and test on its own. The private-client plan (`CL` rows) now lives in the `api` module: its catalog, search, replica and application-profile meaning is FileSquid's application layer behind `filesquid-api`. Task IDs from the pre-switch plan are unchanged; tasks moved between phases rather than being renumbered. New tasks have new IDs (`Task FS-…`, `Task AR-…`; module rows `API-`, `SV-`, `UI-`, `DE-F…`, `PD-FS…`).

Distributions plan their own UI work. This file sequences FileSquid only: it does not dispatch ImageSquid rows (`IS-` rows). ImageSquid's views, its sequence and the FileSquid tasks each of its rows waits on are in the ImageSquid distribution's own plan, which moves with ImageSquid to its own repository in Task FS-3.8.

### Product layers and library allocation (ADR 001 as amended by ADRs 029–032)

FileSquid is one product with three layers ([ADR 029](./architecture/029-filesquid-unified-product-and-distributions.md)):

| Layer | Location | Used by | MUST NOT |
|---|---|---|---|
| Distributions (UI only) | `apps/filesquid/ui` (default), `apps/imagesquid`, later `apps/arkrim` | Desktop webview, server-served static files, later the encrypted browser host | Contain Rust, server code or direct module calls; call anything except the FileSquid API ([ADR 031](./architecture/031-vanilla-typescript-ui-and-white-label-theming.md)) |
| API | `filesquid-api` | Both hosts; later the WASM browser host | Depend on a distribution; expose filesystem paths or SQL to a UI ([ADR 030](./architecture/030-filesquid-api-and-transports.md)) |
| Hosts | `filesquid-desktop` (Tauri 2, custom URI scheme, no TCP port), `filesquid-server` (Axum, multi-user), roadmap encrypted browser host | Owners, self-hosters, institutions | Re-implement API meaning; the desktop MUST NOT open a TCP port unless ADR 030 records otherwise |
| Modules | `filesquid-core`, `filesquid-ocfl`, `filesquid-metadata`, `filesquid-prov`, `filesquid-c2pa`; later media, import/migration, clipping, AI connections, curation jobs, sync | `filesquid-api` | Take a default dependency on another module (optional ones only: the metadata module's `ocfl` store and the prov module's `ocfl` feature, [ADR 040](./architecture/040-prov-o-history.md)); depend on any UI |
| Native processing | `filesquid-native` at `apps/filesquid/crates/native` (name confirmed by the owner 2026-10-18; was `imagesquid_native`; created by [CL-0.1](../apps/filesquid/crates/api/resources/plan.md), grown by [DE-0.8](../apps/filesquid/crates/desktop/resources/plan.md)) | Desktop host (with the `desktop` feature); `filesquid-server` with default features only (SQLite journal store, data-directory checks, `HostMonitor`; its `unit_native_features` test fails if it enables `desktop`), the SQLite journal store until its PostgreSQL operational store lands in [SV-F1.2](../apps/filesquid/crates/server/resources/plan.md) ([ADR 033](./architecture/033-activity-journal-and-live-health-monitoring.md) amendment 2026-10-18) | Be linked into `filesquid-api`, WASM or the ciphertext-only hosted service |
| Ciphertext-only hosted service | `*.filesquid.tech` (crate created by [SV-F4.1](../apps/filesquid/crates/server/resources/plan.md)) | Hosted backup and sync users | Link any module that processes private plaintext, parse OCFL, or hold library keys ([ADR 032](./architecture/032-hosting-and-privacy-model.md), [ADR 004](./architecture/004-axum-hosted-ciphertext-mailbox.md)) |

Native I/O (SQLite storage, the local-filesystem OCFL backend, libvips, FFmpeg, OS adapters) belongs to native processing, not to the Tauri host crate's public API. OCFL, metadata and C2PA logic belongs to the module crates, which `filesquid-api` drives with host-injected storage backends ([ADR 025](./architecture/025-client-side-filesquid-engines.md), amended by ADR 032). Application meaning (catalog, search, replica, the FileSquid OCFL application profile) is implemented once behind `filesquid-api` and reused by every host.

`apps/filesquid/` MUST stay extractable to its own repository, and each distribution MUST stay extractable. Module crates stay independently publishable ([C-047](./product-vision.md#module-rules), [C-048](./product-vision.md#module-rules), [C-054](./product-vision.md#module-rules)); per-engine repository extraction is superseded (Task 10.4).

Phases follow the PRD [release order and dependency gates](./prd.md#release-order-and-dependency-gates). Requirement IDs stay independent of schedule ([decoupled-execution](../.agents/rules/decoupled-execution.md)). Execute **module** tasks for code; use this file to sequence work and to close a phase.

### Release sequence assumptions (do not reorder)

- **MVP (early access):** the default FileSquid distribution on the macOS desktop host only, unsigned DMG, no server ([C-056](./product-vision.md#release-sequence), [ADR 035](./architecture/035-macos-first-desktop-mvp.md)). Linux and Windows desktop follow it.
- **First consumer release:** FileSquid (API plus the default Drive-style UI, with the OCFL and metadata modules, on desktop and `filesquid-server`) ([C-025](./product-vision.md#release-sequence)). C2PA is not in the MVP or the first consumer release ([ADR 037](./architecture/037-c2pa-in-release-2.md)).
- **First hosted service:** encrypted backup and/or sync at `*.filesquid.tech`, delivered as FileSquid features before the ImageSquid release. The same account model scales from personal to institutional volume ([C-031](./product-vision.md#platforms-originals-and-service-limits)). Backup and sync stay distinct.
- **Second consumer release:** ImageSquid, as a FileSquid distribution, together with the FileSquid `c2pa` module (Content Credentials: read, validate, import-time records, signing, edits, scans, the `generator:` search operator and the Content Credentials panel; phase C; `filesquid-c2pa` is added to FileSquid then and reaches the ImageSquid distribution and UI only through `filesquid-api`; [ADR 037](./architecture/037-c2pa-in-release-2.md)).
- **Next service layer:** version-compliant curation jobs on the owner's OCFL collection, Parquet projection and FAIR reporting, delivered as FileSquid modules with the Arkrim dashboard as their primary UI ([C-051](./product-vision.md#platforms-originals-and-service-limits)).
- **Later order:** after the ImageSquid release, the owner chooses the order of Arkrim, IIIF/GLAM and ProofMode at Task 9.0 ([C-052](./product-vision.md#release-sequence)). Whether the encrypted browser host (F5) must precede the ImageSquid release is not decided; the default is that it does not.

### Session procedure

Paste **one** Agent Prompt per agent session. Finish tests, Walkthrough, checkbox, commit, and push before starting the next session.

1. Open this file and take the next unchecked global task whose **Dependencies** are complete. Skip rows marked **Superseded**; execute their replacement instead.
2. Read that task's **Description**. Open each linked module task in the listed order.
3. Copy that module task's **Agent Prompt** into a new agent session. The prompt starts with `@AGENTS.md`. The agent MUST load [AGENTS.md](../AGENTS.md) and every markdown file in [`.agents/rules/`](../.agents/rules/), then keep its work inside the named module directory. Cargo commands run from `apps/filesquid/` with `-p <crate>`; npm commands run inside `apps/filesquid/ui/`.
4. The same prompt tells the agent to invoke `@feature-writer` so SRS rows become executable Gherkin under that module's `tests/features/`.
5. Follow the [Shared agent prompt contract](#shared-agent-prompt-contract) on every session.
6. When the slice is done, the module prompt requires:
   - `<module dir>/resources/tasks/Task-<ID>-Walkthrough.md` (for example `apps/filesquid/crates/ocfl/resources/tasks/`, `apps/filesquid/ui/resources/tasks/`) with the SRS **ID and full human-readable title** at heading 2, plus raw CLI test output
   - deletion of that task's transient `Plan.md` and `ToDos.md`
   - checking the `- [ ]` box in that module's `resources/plan.md`
   - a Conventional Commit and `git push` of the feature branch to origin
7. After **every** linked module task for that global row is checked, check the global box in this file.

### What to paste: module prompts versus global prompts

For code, paste the **module** Agent Prompt. Do not paste the global Agent Prompt as a substitute for `CO-0.1`, `UI-F2.2`, or the other prefixed tasks. Module prompts produce one branch per module slice, which is the Branch-Per-Task rule.

Each global task also has an Agent Prompt. That prompt is a **phase closer / coarse instruction**. Use it when:

- the Description names a single-module range you will complete in one sitting, or
- the module boxes are already checked and you are only ticking the global row and pushing a docs-only checkbox commit.

Until the module boxes are checked, the global row stays open even if someone already ran the global Agent Prompt.

### What `@AGENTS.md` and `@feature-writer` do

They are not a second plan. They are instructions **inside** each Agent Prompt.

- `@AGENTS.md` — load project principles and `.agents/rules/` (branch-per-task, TDD, relative links, OCFL snapshot versus job checkpoint vocabulary, SHA-256, Promtail MUST NOT, no silent restore of owner edits).
- `@feature-writer` — translate the task's Related Requirements into executable BDD feature files under the current module's `tests/features/` (`apps/filesquid/crates/<crate>/tests/features/`, or `apps/filesquid/ui/tests/features/`).

## Shared agent prompt contract

Every task Agent Prompt below is complete. Apply these rules on every implementation task:

1. Branch-per-task (`feat/<id>-<slug>`, or another permitted Conventional Commit type; never `task/` or `claude/`), Conventional Commits, push the feature branch to origin.
2. Keep work inside the named module directory. Cargo commands run from `apps/filesquid/` with `-p <crate>`; `cargo fmt --all` and `cargo clippy --workspace --all-targets --locked -- -D warnings` cover the whole workspace. npm commands run inside `apps/filesquid/ui/`.
3. Search [resources/architecture/](./architecture/) before denying a technology.
4. TDD: failing tests first; lint with rustfmt/Clippy or Prettier/ESLint before tests ([ADR 019](./architecture/019-coding-style-and-lint.md)).
5. Invoke `@feature-writer` for functional work. Gherkin lives under each module's `tests/features/`.
6. UI tests: Playwright against `npm run build` + `vite preview`, strict DOM and state assertions (custom element defined, label from the active label table, computed token values for light and dark, no console errors). UIs are vanilla TypeScript custom elements with no UI framework ([ADR 031](./architecture/031-vanilla-typescript-ui-and-white-label-theming.md)). Packaged Tauri windows use ADR 017 WebdriverIO/Tauri-service; Playwright preview cannot prove the custom URI scheme or native capabilities.
7. Integration tests for filesystem, SQLite, PostgreSQL, S3, HTTP or WebSocket. Performance uses Criterion/k6 ([ADR 017](./architecture/017-test-runners-and-reporting.md)).
8. Allure/JUnit under `<module dir>/tests/allure-results/` (cleared before each run). Copy raw CLI output into `<module dir>/resources/tasks/Task-<ID>-Walkthrough.md` with SRS **ID and full title** at heading 2. Delete that task's `Plan.md` and `ToDos.md`.
9. Internal names: repository, library, collection, virtual collection, virtual exhibit, file. UIs word them only through a label table. Item type is **file**. Digest is SHA-256. Promtail MUST NOT be adopted ([ADR 014](./architecture/014-stdout-observability.md)). Desktop/local MUST NOT require Grafana/Loki/Prometheus/Redpanda.
10. Do not reverse owner README About text. Do not Dockerize Tauri.
11. Follow the [library allocation](#product-layers-and-library-allocation-adr-001-as-amended-by-adrs-029032). UIs call only the FileSquid API. Application meaning lives behind `filesquid-api`. Native processing lives in the native-processing library. OCFL I/O lives in `filesquid-ocfl`. The Tauri host is the custom URI scheme, capabilities and OS integration only. The ciphertext-only hosted service MUST NOT link `filesquid-ocfl`, `filesquid-metadata`, `filesquid-c2pa` or `filesquid-api` read paths over private plaintext.
12. When you check off a module or global box, tick the matching box in [implementation-plan-checklist.md](./implementation-plan-checklist.md) (repository root `resources/`) in the same commit. ImageSquid (`IS-`) and Arkrim (`ARK-`) view rows are not listed there.
