# FileSquid architecture decisions

Architecture Decision Records (ADRs) for FileSquid, the product this repository delivers: one Rust backend with one API, the `ocfl`, `metadata` and `c2pa` modules, desktop and server hosts, and white-label UI distributions (FileSquid default, ImageSquid, later Arkrim) ([ADR 029](./029-filesquid-unified-product-and-distributions.md)). ADRs 001–028 were written when ImageSquid was the product. They now use the FileSquid name wherever they mean the product, and ImageSquid only where they mean the distribution. They keep their filenames, and their Status sections keep the dated revision history and record which later ADR amends or supersedes them. ADR 030 is **Accepted** after transport spike S1; two S1 measurements remain open gates (see its S1 results). These records do not install software. **Accepted** means implementation direction. It is not evidence that [U-11](../product-vision.md#platform-ownership-and-access) or [T-010](../product-vision.md#performance-acceptance) have been measured.

Product requirements remain in the [FileSquid vision](../product-vision.md); the ImageSquid distribution has its own vision, PRD and SRS. The regenerated [PRD](../prd.md), [SRS](../srs.md) and complete-product [architecture document](../architecture.md) are in this tree. Component names for an installation, a user's files, a storage grouping, a saved query and a stored item are defined in [vision terminology](../product-vision.md#terminology). These ADRs MUST use the internal names (repository, library, collection, virtual collection, virtual exhibit, file) when they describe those components. The item type is **file**. A distribution's label table MAY show other names; ImageSquid labels a given file photo, image, or video ([ADR 031](./031-vanilla-typescript-ui-and-white-label-theming.md)).

Rejected as application stacks: Phoenix, LiveView, FastAPI, Python sidecars, Electron, Flutter, React, Svelte (superseded by [031](./031-vanilla-typescript-ui-and-white-label-theming.md)), other UI frameworks, ImageMagick, and as the telemetry stack Promtail, Redpanda, Loki, Grafana, Alloy and Prometheus ([033](./033-activity-journal-and-live-health-monitoring.md)). Vanilla TypeScript is no longer rejected; it is the UI stack ([031](./031-vanilla-typescript-ui-and-white-label-theming.md)). Git, git-annex, Git LFS and shelled-out OCFL CLIs are not FileSquid's OCFL library ([016](./016-rust-ocfl-library.md)).

Still **not** stack ADRs (later): named cloud region, payment provider, HTTP recorder implementation, ONNX/model packs, [FE-042](../product-vision.md#paid-c2pa-publication-watermarking-and-ai-disclosure) publisher, job SQL columns, SPA-asset signing, `filesquid-server` account store and datastore. **Decided inside an existing ADR:** the API contract generators (owner decision 2026-10-17, [030](./030-filesquid-api-and-transports.md)): the TypeScript types are generated with `openapi-typescript`, pinned to an exact version; there is no Rust generator, and the hand-written contract is checked by drift tests. **Gates inside existing ADRs:** independent crypto-protocol audit before hosted pilot ([009](./009-cryptography-webcrypto-compatible-suite.md)); FOSS/patent review of the linked installer before a public desktop binary, including the early-access MVP DMG ([011](./011-native-media-adapters-and-ffmpeg-license.md), [035](./035-macos-first-desktop-mvp.md)).
