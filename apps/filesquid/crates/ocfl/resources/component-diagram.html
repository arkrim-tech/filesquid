filesquid-ocfl component diagram

OCFL module of FileSquid · apps/filesquid/crates/ocfl · drawn against the code on filesquid-product · 2026-10-15

filesquid-ocfl is the ocfl module of FileSquid: an OCFL 1.1 library for reading, writing, validating and browsing preservation storage that still builds, tests and publishes on its own (ADRs 016, 023, 029). FileSquid UIs reach it only through the one FileSquid API (filesquid-api, ADR 030), served by the filesquid-desktop and filesquid-server hosts. Today it has the Git guard (no .git in a storage or object root, and no soft links, hard links or empty directories in the storage hierarchy; IO-0.2), the async storage backend trait with local filesystem and in-memory backends (IO-0.1), and the OCFL 1.1 file formats: SHA-256 and SHA-512 digests, a strict inventory parser that names the OCFL validation code of each refusal, digest sidecars and NAMASTE declarations (IO-0.3); and read and browse: storage-root open with object discovery, object open with the published-head checks, logical state at a caller-pinned version resolved through the inventory, streamed and copied logical files checked against their digests, version history and diffs (IO-0.4); and structural validation that reports every OCFL 1.1 rule an object breaks with its E### or W### code, checked against every object of the pinned community fixtures committed as test data (IO-0.5). The path-based logical-file helpers go through the filesystem backend. The git-like change model, the S3-compatible backend and the API routes are planned. The Drive-style browser is the <fs-file-browser> custom element in @filesquid/ui.
