# Implementation Plan: filesquid-ocfl

The `ocfl` module of FileSquid and a stand-alone FOSS OCFL 1.1 library and tool for the digital preservation community (Cargo package `filesquid-ocfl`, import `filesquid_ocfl`). It owns **storage facts** only ([C-055](../../../../../resources/product-vision.md#module-rules)). It reads, browses, validates and writes on local filesystem and S3-compatible object storage through one async storage backend interface. Git MUST NOT be the OCFL library. `filesquid-api` links it in the desktop host and in `filesquid-server`, and the encrypted browser host links its `wasm32` build; the ciphertext-only hosted service at `*.filesquid.tech` MUST NOT link it ([ADR 025](../../../../../resources/architecture/025-client-side-filesquid-engines.md), [ADR 032](../../../../../resources/architecture/032-hosting-and-privacy-model.md)). It MUST take no default dependency on another FileSquid module and MUST build, test and publish on its own; other programmes MUST be able to install the library and CLI without the FileSquid app ([C-047](../../../../../resources/product-vision.md#module-rules), [T-042](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence), [ADR 023](../../../../../resources/architecture/023-filesquid-ocfl-engine-and-parquet.md)). Per-engine repository extraction is superseded; `apps/filesquid/` as a whole stays extractable. Global sequence: [implementation-plan.md](../../../../../resources/implementation-plan.md).

Cargo commands run from `apps/filesquid/` with `-p filesquid-ocfl` (`cargo test -p filesquid-ocfl --locked`; `cargo build -p filesquid-ocfl --target wasm32-unknown-unknown --no-default-features`). Integration tests against real directories (and later MinIO/S3 fixtures). Conformance tests run against the pinned `1.1/` tree of the community [OCFL fixtures](https://github.com/OCFL/fixtures) ([OCFL-S-009](./srs.md)–[OCFL-S-011](./srs.md)). Community validators (`rocfl`, `ocfl-py`) check objects the engine writes; they MUST NOT be the writer.
