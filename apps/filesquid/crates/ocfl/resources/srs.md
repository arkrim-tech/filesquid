# filesquid-ocfl SRS (scaffold)

The `ocfl` module of FileSquid. Parent: [SRS-F-051](../../../../../resources/srs.md#srs-f-051-ocfl-module).

| Local requirement | Parent |
|---|---|
| OCFL-S-001 Git MUST NOT be the OCFL library; `.git` MUST NOT appear in an OCFL object or storage root. The guard covers the storage root, the storage-hierarchy directories between the storage root and the object roots, and each object root. A `.git` entry inside an object's preserved content (for example an archived Git repository under `v1/content/`) is content and MUST be allowed (owner decision, 2026-10-18). It may hold only ordinary files and non-empty directories: soft links, hard links and empty directories inside it are refused like anywhere else in the storage hierarchy. Hard links, soft links and empty directories MUST NOT be used under the storage hierarchy. | [PRD F-042](../../../../../resources/prd.md#f-042-ocfl-preservation-and-portable-recovery), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md) |
| OCFL-S-002 Digest algorithm is SHA-256: objects the engine writes MUST use `sha256` for content addressing and inventory sidecars. The engine MUST read objects that use `sha256` or `sha512`, the OCFL 1.1 content-addressing algorithms. Inventory, sidecar, NAMASTE and `head` types MUST match OCFL 1.1, and a broken OCFL rule MUST be refused with its OCFL 1.1 validation code (parsing bounds: OCFL-S-017). | [PRD TC-004](../../../../../resources/prd.md#tc-004-decision-status-and-repository-alignment) |
| OCFL-S-003 Default public API is generic OCFL 1.1. FileSquid application-layer types (file objects, recipes, C2PA records, collection snapshots, catalog) and distribution types MUST NOT be required. The crate MUST remain a stand-alone FOSS library and tool, installable without the FileSquid app, and MUST build, test and publish on its own. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [ADR 023](../../../../../resources/architecture/023-filesquid-ocfl-engine-and-parquet.md), [C-047](../../../../../resources/product-vision.md#module-rules), [T-042](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence) |
| OCFL-S-004 Logical state MUST be inventory-driven at a caller-pinned version; stream logical files; enumerate committed logical state. A reader MUST resolve logical paths through the root inventory's `state` and `manifest` only (never by directory names), so bytes kept in an earlier version directory resolve and files the inventory does not list are not logical state. Only the root inventory commits a version: a `vN` above its `head` is unpublished and MUST NOT be readable, the root sidecar MUST match the root inventory (E058, E060, E061), and a head version inventory, when present, MUST equal the root inventory (E064). Logical files MUST stream in chunks of at most 8 MiB and MUST be refused with E092 when their bytes do not match the inventory digest; a copy MUST NOT be published unless every byte matched. Opening a storage root or an object MUST run the Git and hierarchy guards (OCFL-S-001). The enumerator of committed logical state MUST yield, for each committed logical file, the object identifier, version, logical path, digest and content locator, from each object's committed `head` or from every committed version as the caller chooses, in a fixed order (object root, then version oldest first, then logical path); it MUST read from the storage root alone through the storage backend, MUST NOT require SQLite, PostgreSQL or application types, and MUST hold at most one object's inventory at a time. An object that cannot be read MUST be reported with its object root, and with its OCFL validation code when it breaks an OCFL rule (an engine bound or a backend failure carries none), without stopping the enumeration of the other objects. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [T-039](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence) |
| OCFL-S-005 Default dependencies MUST exclude Arrow, Parquet, DuckDB and Iceberg. Later `parquet` feature is default off. Analytical outputs MUST stay outside OCFL reserved paths. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [C-045](../../../../../resources/product-vision.md#module-rules), [C-046](../../../../../resources/product-vision.md#module-rules) |
| OCFL-S-006 FileSquid MUST compile the library crate (a workspace path dependency, or the published version). FileSquid MUST NOT shell out to `fsquid` for canonical OCFL I/O. Release `fsquid` binaries (built by `filesquid-cli`, [ADR 036](../../../../../resources/architecture/036-single-fsquid-cli.md)) are for independent install; this crate ships no binary. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [T-043](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence) |
| OCFL-S-007 The engine MUST reach bytes only through an async, runtime-agnostic storage backend interface (local filesystem on native; S3-compatible on native and `wasm32`; in-memory for tests). The engine core MUST NOT call `std::fs`, `tokio::fs` or a network client directly, and MUST build for `wasm32-unknown-unknown` with default features off. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [SRS-F-051](../../../../../resources/srs.md#srs-f-051-ocfl-module), [C-053](../../../../../resources/product-vision.md#module-rules), [ADR 025](../../../../../resources/architecture/025-client-side-filesquid-engines.md) |
| OCFL-S-008 The engine MUST run behind `filesquid-api` in the desktop host, in `filesquid-server` and (as `wasm32`) in the encrypted browser host. It MUST NOT run in the ciphertext-only hosted service at `*.filesquid.tech`. Browser storage (OPFS, IndexedDB) MUST NOT be a canonical storage root. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [SRS-F-051](../../../../../resources/srs.md#srs-f-051-ocfl-module), [C-053](../../../../../resources/product-vision.md#module-rules), [ADR 025](../../../../../resources/architecture/025-client-side-filesquid-engines.md), [ADR 032](../../../../../resources/architecture/032-hosting-and-privacy-model.md) |
| OCFL-S-009 Validator conformance. The engine validator MUST be tested against every object in the `1.1/` tree of the community [OCFL fixtures](https://github.com/OCFL/fixtures) at the pinned commit (OCFL-S-011). (a) Every object in `good-objects/` MUST validate with zero errors. (b) Every object in `warn-objects/` MUST validate with zero errors and MUST report each warning code named in its directory prefix (for example `W001_W004_W005_zero_padded_versions` reports `W001`, `W004` and `W005`). (c) Every object in `bad-objects/` MUST be rejected as invalid. The report SHOULD include each error code named in its directory prefix (for example `E058_no_sidecar` reports `E058`). The fixtures README allows a validator to stop early and miss a named code, so a missing prefix code is not a failure if the object is rejected. Each such gap MUST be listed per fixture in the task Walkthrough. (d) Errors and warnings MUST use the OCFL 1.1 validation codes (`E###`, `W###`). (e) A fixture MUST NOT be skipped or excluded unless the Walkthrough names it with a stated reason. (f) The validator MUST report every broken rule it finds as a finding with its code and location rather than stop at the first, except within one inventory, which is checked to its first broken rule; it MUST return an error without findings only when the object cannot be validated (a backend failure, an engine bound of OCFL-S-017, or an OCFL version other than 1.1). (g) Only the root inventory commits a version: a version directory the root inventory does not list MUST be reported (E046) even when it holds its own inventory and sidecar. (h) Fixity values in every algorithm of the OCFL 1.1 fixity table (`md5`, `sha1`, `sha256`, `sha512`, `blake2b-512`) MUST be verified against the content (E093); values in other algorithms MUST be ignored (E028). The engine reads these algorithms only and writes `sha256` (OCFL-S-002). (i) Every stated digest MUST be checked against the bytes: the root manifest and the manifests of earlier version inventories, whatever their digest algorithm (E092). | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md), [ADR 023](../../../../../resources/architecture/023-filesquid-ocfl-engine-and-parquet.md), [OCFL 1.1 validation codes](https://ocfl.io/1.1/spec/validation-codes.html) |
| OCFL-S-010 Read and write conformance. (a) For every `1.1/good-objects/` fixture, the engine MUST resolve the logical state of every version from `v1` to `head` through inventory `state` and `manifest`. Every logical file it streams MUST match the inventory digest. (b) For every `1.1/content/` fixture, the engine MUST write one OCFL object version per content version directory. Each written object MUST validate with zero errors in the engine validator and in at least one independent community validator (`ocfl-validate` from `ocfl-py`, or `rocfl validate`). Its logical state at each version MUST equal the source content directory. Byte-identical inventories are not required: `created` timestamps and digest choices may differ. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [T-039](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence), [ADR 023](../../../../../resources/architecture/023-filesquid-ocfl-engine-and-parquet.md) |
| OCFL-S-011 Fixture pinning and handling. The fixtures MUST be pinned to one commit of `OCFL/fixtures` (initial pin `d323fc207126becec066998b43408d998bf0fb1b`, 2024-12-05T17:25:06Z, the latest published set; it covers OCFL 1.0 and 1.1). Moving the pin MUST be its own reviewed change that reruns OCFL-S-009 and OCFL-S-010. Fixtures are test data under `tests/`. They MUST NOT be compiled into, packaged with, or loaded by the library or CLI at runtime. `cargo test --locked` MUST run the conformance suite offline once the pinned fixtures are present locally. The local pre-commit hook MUST run it in this repository and in any repository `apps/filesquid/` is later extracted to; no hosted CI is used. Fixture licence (CC-BY-4.0) attribution MUST be kept with the copied fixtures. `1.0/` fixtures are out of scope unless a later requirement adds OCFL 1.0 object support. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [ADR 023](../../../../../resources/architecture/023-filesquid-ocfl-engine-and-parquet.md), [T-042](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence) |
| OCFL-S-012 The engine MUST expose a serializable UI view API (folder listing by logical-path prefix with paging, file details, version history, size, fixity, ranged reads, version-producing writes) that returns storage facts only: object identifier, logical path, versions, version `created`, `user` and `message`, digests and fixity, size and content location. It MUST NOT extract embedded or descriptive metadata; an extension-based type label is a display hint only. `filesquid-api` routes this view API to every UI. | [F-055](../../../../../resources/prd.md#f-055-default-ui-and-panel-composition), [C-055](../../../../../resources/product-vision.md#module-rules), [ADR 028](../../../../../resources/architecture/028-filesquid-ui-packages-and-panel-composition.md) |
| OCFL-S-013 FileSquid MUST provide a presentation-only Drive-style browser (navigation, breadcrumb, list and grid views, preview, Details and Versions panels) with named sidebar panel slots, built as vanilla TypeScript custom elements in `@filesquid/ui` (`<fs-file-browser>`), reaching this engine only through the FileSquid API. The browser MUST NOT depend on the Metadata or Content Credentials panels. | [F-055](../../../../../resources/prd.md#f-055-default-ui-and-panel-composition), [ADR 028](../../../../../resources/architecture/028-filesquid-ui-packages-and-panel-composition.md), [ADR 031](../../../../../resources/architecture/031-vanilla-typescript-ui-and-white-label-theming.md) |
| OCFL-S-014 Delta computation. Given a working state (a directory or a set of logical files) and a base version, the engine MUST compute the change set by digest, classifying each logical path as added, changed, renamed, deleted or reinstated. It MUST write only bytes whose digest is not already in the object's `manifest`. Renames, deletes and reinstatements MUST change the new version's `state` only and MUST NOT copy bytes. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md), [FileSquid U-51](../../../../../resources/product-vision.md#ocfl-module) |
| OCFL-S-015 Change-model API. The library MUST expose stage, status, diff (staged changes against `head`, and between any two versions), commit, log, checkout, revert and reinstate as a documented public API. Each commit MUST publish exactly one new OCFL version. Revert and reinstate MUST commit a new version that points logical paths at existing `manifest` entries and MUST NOT modify or remove earlier versions. The staging area and checkout output MUST be outside the storage root, and staging MUST NOT be stored as an OCFL extension inside the object. Reading or recovering an object MUST NOT require staging data. `fsquid` MUST use only this public API. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md), [FileSquid U-52](../../../../../resources/product-vision.md#ocfl-module), [T-043](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence) |
| OCFL-S-016 Concurrent commits. Every commit MUST go through the `vN` reservation and head compare-and-swap on every storage backend. If the staged change set's base `head` is no longer current, the engine MUST rebase it onto the new `head` when no staged logical path changed in the intervening versions, and otherwise MUST report a conflict without publishing. Native builds, `wasm32` builds and the view API's version-producing writes (OCFL-S-012) MUST use this same change model; there MUST be no second write path. | [PRD F-051](../../../../../resources/prd.md#f-051-ocfl-module), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md), [ADR 012](../../../../../resources/architecture/012-s3-compatible-ciphertext-storage.md), [ADR 025](../../../../../resources/architecture/025-client-side-filesquid-engines.md), [FileSquid U-53](../../../../../resources/product-vision.md#ocfl-module) |
| OCFL-S-017 Untrusted OCFL files MUST be parsed within fixed bounds: an inventory above 64 MiB and a digest sidecar above 4 KiB MUST be refused before they are read, JSON nesting deeper than 8 objects or arrays MUST be refused while parsing, and a JSON object that repeats a key MUST be refused. A refusal because of these engine bounds carries no OCFL validation code; every refusal for a broken OCFL rule MUST carry its OCFL 1.1 code. Error messages MUST NOT echo unbounded input such as a repeated key. | [PRD NFR-004](../../../../../resources/prd.md#nfr-004-security-and-privacy), [OCFL-S-002](./srs.md) |
| OCFL-S-018 Write order and unpublished versions. A writer MUST reserve `vN` before it writes any `vN` byte or any object-root byte for that version. The reservation MUST be exclusive and fenced: on a local filesystem a per-object lease, on S3-compatible storage a compare-and-swap reservation or a host-supplied PostgreSQL generation, kept outside the storage root. The reservation MUST be checked again immediately before every write under `vN/` and before each root write; head compare-and-swap alone is not sufficient. A writer whose lease expired, was reassigned, or has no more than its safety margin left MUST NOT start another write of `vN` content or of the root head. Writes under `vN/` MUST NOT overwrite, and the root inventory and root sidecar MUST be compare-and-swaps. **Known gap (owner decision, 2026-10-18).** Where the storage does not check the fencing token itself, only the writer checks it: a writer that stalls longer than its safety margin between its last check and its next write can still make that one write after its reservation has passed to another writer. That write cannot replace another writer's content, inventories or head, but it can leave a file under `vN/` that the published inventory does not list, which the validator MUST report as E023, and a stalled writer that is recovering an unpublished `vN` can delete a leftover file the new holder had already checked. The gap is accepted only while a library cannot be written by more than one host process or by more than one user, and only on these conditions: (1) before a library can be written by more than one host process or by more than one user, every write under `vN/`, every delete made while reconciling an unpublished `vN`, and every root write to that library MUST be refused by the storage, or by the service that performs or authorises the write in the same atomic step, when the writer's fencing token is no longer current (for example S3 conditional writes, or a host PostgreSQL generation checked in the same atomic step as the write); a check made only by the writer before its write does not satisfy this; (2) every validator error, E023 included, MUST reach the host's health status and the Monitor ([API-S-022](../../api/resources/srs.md)). A committed head that has no version inventory of its own (OCFL allows that, W010) MUST NOT be the base of a commit: the writer MUST refuse it before any write, because readers need that file to read past an interrupted publication; the consented repair in OCFL-S-020 lifts this refusal (a repaired sha256 object becomes editable; a repaired sha512 object is still refused, OCFL-S-002). The writer MUST NOT change `v1`…`v(N-1)` content or inventories (the only exception is the version-inventory repair of OCFL-S-020), MUST assemble the version (digests and inventory) outside the object root first, MUST write only new bitstreams under `vN/`, and MUST write content, then the version inventory and its sidecar, then the root inventory (compare-and-swap) and its sidecar last. While content or a version inventory exists and the root `head` is still `v(N-1)`, or the root sidecar does not match the root inventory, readers MUST treat `vN` as unpublished. Recovery MUST reconcile or replace an unpublished `vN` under a new reservation and MUST NOT publish a second `vN`. | [PRD F-042](../../../../../resources/prd.md#f-042-ocfl-preservation-and-portable-recovery), [PRD NFR-001](../../../../../resources/prd.md#nfr-001-preservation-and-transactional-integrity), [ADR 007](../../../../../resources/architecture/007-durable-jobs-and-interactive-performance.md), [ADR 012](../../../../../resources/architecture/012-s3-compatible-ciphertext-storage.md), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md) |
| OCFL-S-019 Inspection and copy never edit an object. Opening, reading, browsing, validating or copying an object MUST NOT change its inventories, sidecars, declarations or stored content. A copy of a logical file MUST refuse, before it writes any byte, a destination that lies inside an OCFL object root or storage root on the destination backend (a directory above the destination, or the backend root, holding an `0=ocfl_object_<version>` or `0=ocfl_<version>` declaration), whatever the backend. Only the writer (OCFL-S-018) changes an object, and only by adding a version; earlier versions, including signed originals stored in them, stay byte-identical. The one exception is the consented version-inventory repair (OCFL-S-020), which adds only a copy of the root inventory and its sidecar to the head version directory of an object that has none and changes no existing file. | [PRD F-042](../../../../../resources/prd.md#f-042-ocfl-preservation-and-portable-recovery), [T-036](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md) |
| OCFL-S-020 Version-inventory repair. The engine MUST provide a repair for an object whose committed head version has no version inventory (W010), so that the object can become the base of a commit (OCFL-S-018). The repair MUST: run under the same exclusive, fenced reservation as a commit and read the committed head again under it; run every refusal check below before writing anything, also when resuming; treat exactly one shape as a W010 repair in progress rather than as an error: the head version directory holds a version inventory byte-identical to the root inventory, holds no version sidecar or one byte-identical to the root sidecar, and holds no other file the head's inventory does not list; resume that shape by writing only what is missing (a head that already holds both files has nothing missing and MUST be refused as nothing to repair, without writing); refuse, without writing, an object whose root sidecar does not match its root inventory, an object for which the full validator reports any error other than the findings that this exact shape itself causes (content digest errors and every other error included), and any other object whose head already has a version inventory or any other file not listed by its inventory; write into the head version directory only the version inventory and its digest sidecar, each byte-identical to the root inventory and the root sidecar, without overwriting any file, with the reservation checked before each write and the sidecar written last; and change no content, no logical state, no other version directory and no object-root file, and publish no new version. An interrupted repair MUST leave the logical state unchanged and MUST be completed by running the repair again. After a repair the object MUST validate with zero errors and without W010, and a commit on it MUST no longer be refused for the missing version inventory (until the version sidecar of an interrupted repair is written, the writer MUST refuse that head as well): a sha256 object becomes editable, while a sha512 object is repaired the same way but its commits are still refused because the writer extends sha256 objects only (OCFL-S-002). The repair MUST return a receipt (object identifier, version, inventory digest, paths written) to its caller. The engine MUST NOT start a repair by itself, and opening, reading, validating, inspecting or copying an object MUST NOT repair it; the host's application layer runs it only after the owner consents ([API-S-023](../../api/resources/srs.md)). | [PRD F-042](../../../../../resources/prd.md#f-042-ocfl-preservation-and-portable-recovery), [PRD NFR-001](../../../../../resources/prd.md#nfr-001-preservation-and-transactional-integrity), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md), [OCFL-S-018](./srs.md) |
| OCFL-S-021 Opaque bytes; the dual profile is a caller. The engine MUST store the content bytes its caller supplies unchanged and MUST NOT interpret, transform or require any encoding of them: every byte value, empty files, bytes that are not UTF-8 and bytes that look like OCFL files are content. Logical paths are UTF-8 strings that the engine MUST store as given; they MUST pass the OCFL 1.1 path rules (E052, E053), and a caller that hides names MUST encode them to meet those rules. Content digests MUST be computed over exactly the stored bytes (OCFL-S-002), so manifest digests (E092) and fixity values (E093) are verified over ciphertext without a key. Owner-readable local media has no transform: the caller stages its plaintext as is. Only ciphertext hosted packages (sealed content and encoded names) are a transform, applied by the caller (`filesquid-api`) before staging and after reading. Both use the same engine API; the engine MUST NOT define profile, key or encryption object types and MUST NOT depend on an encryption crate. Over ciphertext and encoded logical paths the inventory and digest sidecars MUST remain structurally readable OCFL 1.1 that the engine validator and an independent community validator accept; recovering plaintext is the caller's job. | [PRD F-042](../../../../../resources/prd.md#f-042-ocfl-preservation-and-portable-recovery), [PRD TC-002](../../../../../resources/prd.md#tc-002-endpoint-processing-and-hosted-encryption), [ADR 010](../../../../../resources/architecture/010-ocfl-1-1-dual-profile.md), [ADR 023](../../../../../resources/architecture/023-filesquid-ocfl-engine-and-parquet.md) |
