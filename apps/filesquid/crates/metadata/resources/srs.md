| MD-S-008 Canonical metadata is `metadata.md`: YAML front matter (namespaced maps) plus optional Markdown body, saved by the canonical store (one `<filename>.metadata.md` beside each plain file for `sidecar`; inside the OCFL object for `ocfl`, which FileSquid uses, at the logical path its caller names). FileSquid MUST keep exactly one metadata record per file, `<file-uuid>.metadata.md`, in the same directory as the stored original `<file-uuid>.<ext>` (FileId plus the original extension only when it is 1 to 16 ASCII letters or digits, otherwise no extension; owner decision 2026-10-19). It is the file's only metadata record: the original file name, the display name after a rename, the extension, the format and MIME type, the `import` section (MD-S-013) and the descriptive statements. With the `ocfl` store each edit MUST be a new OCFL version committed through `filesquid-ocfl`; an edit MUST NOT rewrite an earlier version. An edit whose base head has moved MUST be rebased onto the new head (OCFL-S-016); only a concurrent change to the same metadata record MUST be reported as a conflict, and nothing MUST be overwritten. Approved exception for import commits (owner decision 2026-10-20, [ADR 038](../../../../../resources/architecture/038-import-file-record.md) Decision 10): inside the commit, the store MUST check that the `object_version` each new import entry cites equals the version being committed, so an import commit whose base head has moved MUST NOT be rebased but MUST fail as a retryable conflict that publishes nothing. In a file record (`schema: filesquid.original.v1`) the `schema:` key holds the schema identifier, so Schema.org statements MUST be written under the YAML key `schemaorg:` and MUST be read from either `schemaorg:` or `schema:`; a `metadata.md` without a schema identifier keeps `schema:` (owner decision 2026-10-20, ADR 038 Decision 9). Indexes MUST rebuild from it ([ADR 027](../../../../../resources/architecture/027-filesquid-metadata-pluggable-stores.md)). | [PRD F-052](../../../../../resources/prd.md#f-052-metadata-module), [SRS-F-052](../../../../../resources/srs.md#srs-f-052-metadata-module), [T-046](../../../../../resources/product-vision.md#canonical-ocfl-state-and-evidence) |

The crate MUST NOT run in the ciphertext-only hosted service. | [PRD F-052](../../../../../resources/prd.md#f-052-metadata-module), [SRS-F-052](../../../../../resources/srs.md#srs-f-052-metadata-module), [C-053](../../../../../resources/product-vision.md#module-rules), [ADR 025](../../../../../resources/architecture/025-client-side-filesquid-engines.md) |

| MD-S-012 Namespace registry. An owner, distribution or module MAY register an extension namespace (prefix, IRI, optional term list; for example RiC-O), and an owner MAY declare a custom namespace whose keys are free key:value pairs. A registration MUST NOT redefine `dcterms:`, `dc:`, `schema:` or `exif:`. An extension prefix MUST be unique within a repository and map to exactly one IRI; re-registering an existing prefix with a different IRI MUST be rejected. A namespace with a term list MUST reject unknown terms; a statement whose prefix is not registered MUST be rejected with an error naming the prefix. Schema.org statements keep the prefix `schema:` in every API, interchange format and UI; only their YAML key inside a file record is `schemaorg:` (MD-S-008). Extension statements MUST be stored as their own YAML map in `metadata.md`, MUST round-trip through CSV, JSON and XMP, MUST be covered by the outgoing disclosure policy like `exif:`, `dcterms:` and `schema:` statements, and MUST NOT be mapped onto `dcterms:`. Registrations MUST persist through the canonical store so a rebuilt index recovers them: as the record `filesquid.namespaces.v1` (one JSON registration per line, default `namespaces.md`) at the logical path its caller names, one OCFL version per change, refusing a save that drops a registration, changes its IRI or kind, or drops its term list or a term in it (an open namespace stays open). A prefix MUST also not be a key of the record format (`schemaorg`, `import`, `namespaces` and the file-record header keys), and an IRI MUST NOT be a built-in namespace's IRI or be registered under a second prefix. The crate MUST NOT ship a term list of its own; a distribution registers the vocabulary it needs. The CLI MUST offer `namespace register` and `namespace list`, and `fsquid metadata validate` MUST name every unregistered prefix. | [PRD F-052](../../../../../resources/prd.md#f-052-metadata-module), [SRS-F-052](../../../../../resources/srs.md#srs-f-052-metadata-module), [PRD F-046](../../../../../resources/prd.md#f-046-media-metadata-inspection-correction-and-privacy-exports), [C-043](../../../../../resources/product-vision.md#provenance-metadata-and-disclosure), [FileSquid U-55](../../../../../resources/product-vision.md#metadata-module), [ADR 022](../../../../../resources/architecture/022-dublin-core-descriptive-metadata.md) |
| MD-S-013 Import record. The crate MUST define, validate and persist the append-only `import` section of the file's metadata record `<file-uuid>.metadata.md` (MD-S-008; YAML front matter with a versioned schema identifier) in the file's OCFL object through the `ocfl` store, together with the owner's exact original file name and its Unicode normalisation form, the file extension and the format and MIME type at the top of the record, from facts supplied by the caller: acquisition (record, start and finish times in RFC 3339 UTC; method; job and operation IDs; cited OCFL object, version, logical path, SHA-256 and size), source file (original name and Unicode normalisation form, absolute and relative path, import root, file size in bytes as the source reported it (for a symbolic link or alias, the followed target's size) and as verified from the bytes read and hashed (copied content for a managed import, referenced bytes for a referenced import), where the crate MUST reject a record whose two sizes differ so the import fails verification and stays pending, birth, modified, status-changed, accessed and date-added times, owner and group names and IDs, POSIX mode, ACL, flags, link target, OS content type, extension), source volume (name, UUID, filesystem type, mount point, local, removable or network), extended attributes (name, size, value; UTF-8 names and values as strings, others as base64 marked `encoding: base64`; known ones decoded) and host (OS name, version and build, architecture, host name, account, FileSquid version, build and distribution). Every missing fact MUST be listed as unavailable with a reason. Per acquisition entry, at most 256 attribute names and 1 MiB of attribute value bytes are inspected; values over 64 KiB MUST be stored by size and SHA-256 only; anything cut by these bounds MUST be marked truncated (with the count enumerated) or its digest incomplete, never silently dropped. The crate MUST define the identity classes the outgoing disclosure policy scrubs from an exported or shared copy of the record, each removed fact listed as withheld by policy: paths, account names, host names, numeric IDs, origin URLs, quarantine agents, Finder comments and `OriginalName`, the original file name wherever the record holds it (the header's original name, the display name and each import entry's source file name). Every class MUST be scrubbed by default from shares and publications; `OriginalName` MUST be kept only when the saved outgoing policy selects **Use original filename** (owner decision 2026-10-20, ADR 038 Decision 6). Entries MUST never be edited, and the store MUST refuse a save that changes or removes an existing `import` entry or the recorded original file name; a re-import appends an entry in a new OCFL version (owner decision 2026-10-19: no separate `file-record.md`). The crate MUST NOT read the filesystem itself ([ADR 038](../../../../../resources/architecture/038-import-file-record.md)). | [PRD F-002](../../../../../resources/prd.md#f-002-safe-file-folder-and-device-import), [PRD F-052](../../../../../resources/prd.md#f-052-metadata-module), [SRS-F-052](../../../../../resources/srs.md#srs-f-052-metadata-module), [PRD F-046](../../../../../resources/prd.md#f-046-media-metadata-inspection-correction-and-privacy-exports) |

Without options the store keeps its stand-alone defaults. | [PRD F-067](../../../../../resources/prd.md#f-067-prov-o-history-of-every-version-and-change), [SRS-F-067](../../../../../resources/srs.md#srs-f-067-prov-o-history-of-every-version-and-change), [PRD F-052](../../../../../resources/prd.md#f-052-metadata-module), [ADR 040](../../../../../resources/architecture/040-prov-o-history.md) |
