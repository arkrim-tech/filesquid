| MD-S-010 JSON sidecar import/export MUST ship with CSV and XMP. A sidecar is one UTF-8 JSON document per OCFL object binding `{namespace, term, value}` statements to the OCFL object identifier and the SHA-256 digest of the described logical file. The CLI MUST expose `export json` and `import json`. Import MUST apply the `/terms/` register checks of MD-S-002 and the namespace registry checks of MD-S-012 and MUST reject a sidecar whose digest does not match the target file. Export then import MUST reproduce the same statements. A JSON sidecar is interchange and MUST NOT replace `metadata.md`. | [PRD F-052](../../../../../resources/prd.md#f-052-metadata-module), [C-049](../../../../../resources/product-vision.md#module-rules), [ADR 022](../../../../../resources/architecture/022-dublin-core-descriptive-metadata.md), [ADR 024](../../../../../resources/architecture/024-filesquid-metadata-engine.md) |
| MD-S-011 FileSquid MUST provide a presentation-only Metadata panel over the API's metadata property routes as the vanilla TypeScript custom element `<fs-metadata-panel>` in `@filesquid/ui`, mountable in the default browser's sidebar slot or any distribution's view without depending on another panel. This crate MUST own descriptive and technical file facts (embedded EXIF/ID3/IPTC/XMP, format identification, original creation or capture dates, Dublin Core and Schema.org description, titles, captions, keywords, rights). Application meaning (collections, people, favorites, search indexes, recipes) MUST NOT be owned by this crate; it belongs to FileSquid's application layer. | [F-055](../../../../../resources/prd.md#f-055-default-ui-and-panel-composition), [C-055](../../../../../resources/product-vision.md#module-rules), [ADR 028](../../../../../resources/architecture/028-filesquid-ui-packages-and-panel-composition.md), [ADR 031](../../../../../resources/architecture/031-vanilla-typescript-ui-and-white-label-theming.md) |
| MD-S-012 Namespace registry. An owner, distribution or module MAY register an extension namespace (prefix, IRI, optional term list; for example RiC-O), and an owner MAY declare a custom namespace whose keys are free key:value pairs. A registration MUST NOT redefine `dcterms:`, `dc:`, `schema:` or `exif:`. An extension prefix MUST be unique within a repository and map to exactly one IRI; re-registering an existing prefix with a different IRI MUST be rejected. A namespace with a term list MUST reject unknown terms; a statement whose prefix is not registered MUST be rejected with an error naming the prefix. Extension statements MUST be stored as their own YAML map in `metadata.md`, MUST round-trip through CSV, JSON and XMP, MUST be covered by the outgoing disclosure policy like `exif:`, `dcterms:` and `schema:` statements, and MUST NOT be mapped onto `dcterms:`. Registrations MUST persist through the canonical store so a rebuilt index recovers them. | [PRD F-052](../../../../../resources/prd.md#f-052-metadata-module), [SRS-F-052](../../../../../resources/srs.md#srs-f-052-metadata-module), [PRD F-046](../../../../../resources/prd.md#f-046-media-metadata-inspection-correction-and-privacy-exports), [C-043](../../../../../resources/product-vision.md#provenance-metadata-and-disclosure), [FileSquid U-55](../../../../../resources/product-vision.md#metadata-module), [ADR 022](../../../../../resources/architecture/022-dublin-core-descriptive-metadata.md) |
| MD-S-013 Import file record. The crate MUST define, validate and persist the append-only `file-record.md` (YAML front matter with a versioned schema identifier) in the file's OCFL object through the `ocfl` store, from facts supplied by the caller: acquisition (record, start and finish times in RFC 3339 UTC; method; job and operation IDs; cited OCFL object, version, logical path, SHA-256 and size), source file (original name and Unicode normalisation form, absolute and relative path, import root, file size in bytes as the source reported it (for a symbolic link or alias, the followed target's size) and as verified from the bytes read and hashed (copied content for a managed import, referenced bytes for a referenced import), where the crate MUST reject a record whose two sizes differ so the import fails verification and stays pending, birth, modified, status-changed, accessed and date-added times, owner and group names and IDs, POSIX mode, ACL, flags, link target, OS content type, extension), source volume (name, UUID, filesystem type, mount point, local, removable or network), extended attributes (name, size, value; UTF-8 names and values as strings, others as base64 marked `encoding: base64`; known ones decoded) and host (OS name, version and build, architecture, host name, account, FileSquid version, build and distribution). Every missing fact MUST be listed as unavailable with a reason. Per acquisition entry, at most 256 attribute names and 1 MiB of attribute value bytes are inspected; values over 64 KiB MUST be stored by size and SHA-256 only; anything cut by these bounds MUST be marked truncated (with the count enumerated) or its digest incomplete, never silently dropped. Entries MUST never be edited; a re-import appends an entry in a new OCFL version. The crate MUST NOT read the filesystem itself ([ADR 038](../../../../../resources/architecture/038-import-file-record.md)). | [PRD F-002](../../../../../resources/prd.md#f-002-safe-file-folder-and-device-import), [PRD F-052](../../../../../resources/prd.md#f-052-metadata-module), [SRS-F-052](../../../../../resources/srs.md#srs-f-052-metadata-module) |
