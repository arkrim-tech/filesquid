# filesquid-api SRS (planned)

The single FileSquid API and FileSquid's application layer. | API-S-003 The router MUST be transport-agnostic and mounted unchanged by the desktop host (custom URI scheme) and `filesquid-server` (HTTP). | API-S-004 Every call MUST be authenticated and authorised before files, SQL or keys are touched: per-launch token on desktop; accounts, groups and collection-level permissions on the server. Access MUST be deny-by-default: a host with no installed authoriser MUST refuse every guarded call; every routed operation MUST declare the action it performs (`x-filesquid-action` in the contract) and MUST NOT run its handler before that action is authorised; host-served routes (the event channel, `/metrics`) MUST use the same layer, including for methods they do not accept; the 404 and 405 fallbacks MUST answer only an authenticated caller. The only exception is API-S-015. The credential is `Authorization: Bearer <token>` on any request, WebSocket upgrades included, so non-browser clients can send the header on the upgrade. A browser cannot set headers on a WebSocket, so on an upgrade it MAY instead offer the subprotocol `filesquid.bearer.<token>`, accepted only when `filesquid.events.v1` is offered too; the subprotocol is not a credential for plain HTTP. A present `Authorization` header that is not a usable `Bearer` credential MUST be refused as `invalid_credentials` and MUST NOT fall back to the subprotocol; only a request with neither carrier is `missing_credentials`. Tokens MUST be 256 random bits (64 hex characters), compared as SHA-256 digests in constant time so neither content nor length leaks, and never logged, journaled or echoed; the desktop token MUST be new at every launch, held in memory only and given only to the app's own page origins. A denial MUST be an `ApiError` with a `reason`: `missing_credentials` (401 `unauthorized`), `invalid_credentials` or `not_permitted` (403 `forbidden`), never retryable. | [F-056](../../../../../resources/prd.md#f-056-single-filesquid-api), [SRS-F-056](../../../../../resources/srs.md#srs-f-056-single-filesquid-api), [F-057](../../../../../resources/prd.md#f-057-desktop-and-server-hosts), [F-034](../../../../../resources/prd.md#f-034-family-accounts-and-shared-libraries), FileSquid [U-06](../../../../../resources/product-vision.md#platform-ownership-and-access), [U-18](../../../../../resources/product-vision.md#one-api-hosts-and-distributions), [T-053](../../../../../resources/product-vision.md#api-and-hosts) |

| API-S-015 The liveness probe `GET /api/v1/health/live` MUST be the only public route: it MUST answer without a credential (route action `public`, contract `security: []`) and MUST say only that the process is up (`{"status":"up"}`: no version, component detail or journal). | API-S-016 `FILESQUID_ADMIN_TOKEN`, when set to a non-blank value, MUST be the administrator token on every platform; surrounding whitespace is trimmed, and a blank value counts as unset. The trimmed value MUST have the format of a generated token: exactly 64 hexadecimal characters (256 bits); otherwise the server MUST refuse to start with an error that names the variable and the format and MUST NOT contain the value. A stored token file MUST hold the same format (trimmed; a blank file is a crashed first start, below). When the variable is unset or blank, only on Unix MAY `filesquid-server` read or create `<data dir>/admin-token`; on other platforms it MUST NOT read or write a token file and MUST refuse to start with an error that names `FILESQUID_ADMIN_TOKEN`. On Unix the server MUST open the token file once with `O_NOFOLLOW` and `O_NONBLOCK` (so neither a symbolic link nor a FIFO can redirect or hang the open) and MUST refuse it unless that handle is a regular file owned by the server user with no group or other permission bits; the error MUST name the remedy for that case and MUST NOT contain the token. A first start MUST create the file atomically (`create_new`) and MUST remove a partly written file when the write or sync fails. A blank, owner-only, regular file (left by a crashed first start) MUST be replaced atomically, through a temporary file with a random name that is renamed over it, after a bounded wait of at most 50 rereads 20 ms apart (1 s) for a concurrent writer. Startup MUST NOT delete temporary token files, because one may belong to a concurrent server's recovery; an orphan left by a crash MUST NOT block a later recovery. | [F-056](../../../../../resources/prd.md#f-056-single-filesquid-api), [SRS-F-056](../../../../../resources/srs.md#srs-f-056-single-filesquid-api), [F-057](../../../../../resources/prd.md#f-057-desktop-and-server-hosts), [F-034](../../../../../resources/prd.md#f-034-family-accounts-and-shared-libraries), FileSquid [U-06](../../../../../resources/product-vision.md#platform-ownership-and-access), [U-18](../../../../../resources/product-vision.md#one-api-hosts-and-distributions), [T-053](../../../../../resources/product-vision.md#api-and-hosts) |

Successful calls are not journaled one by one. A refusal before the monitor starts MUST still be printed to stdout, regardless of the log level. | [F-056](../../../../../resources/prd.md#f-056-single-filesquid-api), [SRS-F-056](../../../../../resources/srs.md#srs-f-056-single-filesquid-api), [F-057](../../../../../resources/prd.md#f-057-desktop-and-server-hosts), [F-034](../../../../../resources/prd.md#f-034-family-accounts-and-shared-libraries), FileSquid [U-06](../../../../../resources/product-vision.md#platform-ownership-and-access), [U-18](../../../../../resources/product-vision.md#one-api-hosts-and-distributions), [T-053](../../../../../resources/product-vision.md#api-and-hosts) |
