| API-S-019 Library domain commands and queries. The application layer MUST define versioned commands (a `filesquid-core` `CommandEnvelope` plus the command) to create a library, to create, rename and delete collections and virtual collections, to add and remove members of a hand-picked virtual collection, and to hide, unhide, delete, restore and permanently delete files; and versioned queries (a `QueryEnvelope`, an opaque cursor and the query) to list a repository's libraries, open a library, list its collections and virtual collections, list files of the library, a collection, a virtual collection or the unfiled files, and read the deletion policy. It MUST store through a catalog the host injects and MUST NOT carry a filesystem path or SQL. New library, collection and virtual-collection identifiers MUST be UUID v4 from the OS CSPRNG (CORE-S-001). Every command except create-library MUST name its library, and every folder, collection, virtual collection or file it names MUST belong to that library, or the command is `not_found`. Create-library MUST send expected revision `0`, and its commit MUST find the library absent; any other command whose expected revision is not the library's current revision MUST be refused as `conflict` with no change. A repeated operation ID of a command that changed something MUST answer the first outcome (including `deleted_at` and `purge_after`) with no second change; the catalog MUST answer a stored receipt before it checks the revision. A failed commit MUST leave the catalog unchanged. Names and titles MUST be 1 to 1,024 bytes and not blank; a file batch MUST name 1 to 1,000 distinct files. Deleting a collection MUST retain its files, which become unfiled; deleting a virtual collection MUST retain its members; removing a file from a virtual collection MUST NOT change its collection or other memberships; a rule-based virtual collection MUST refuse hand-picked membership changes. Deleted files MUST stay recoverable until their `purge_after` time, 30 days after deletion by default, unless an explicit confirmed permanent deletion removes them earlier; deletion MUST answer `deleted_at` and `purge_after` (RFC 3339 UTC) of the files it newly deletes; a file in the batch that is already deleted MUST keep its earlier times, which the deleted view reports per file; restore MUST keep the hidden flag. Permanent deletion MUST apply only to recoverably deleted files and MUST carry a confirmation naming the library and the exact file count. The ordinary view MUST exclude hidden and deleted files; the hidden view lists hidden files that are not deleted; the deleted view lists deleted files. Listings MUST page 1 to 1,000 items in a stable (order, ID) order, with no repeat or gap across pages, and refuse a malformed cursor. A command that changes nothing (for example a rename to the same title or adding a present member) MUST meet the revision rule when it is committed (a revision that moved on after planning is `conflict`), MUST answer `committed` at the current revision with no new revision, and MUST store nothing: no operation-ID receipt, no journal entry and no OCFL version (owner decision, 2026-10-19, an explicit exception to the activity-journal rule of [ADR 033](../../../../../resources/architecture/033-activity-journal-and-live-health-monitoring.md)).
