| API-S-016 `FILESQUID_ADMIN_TOKEN`, when set to a non-blank value, MUST be the administrator token on every platform; surrounding whitespace is trimmed, and a blank value counts as unset. The trimmed value MUST have the format of a generated token: exactly 64 hexadecimal characters (256 bits); otherwise the server MUST refuse to start with an error that names the variable and the format and MUST NOT contain the value. A stored token file MUST hold the same format (trimmed; a blank file is a crashed first start, below). When the variable is unset or blank, only on Unix MAY `filesquid-server` read or create `<data dir>/admin-token`; on other platforms it MUST NOT read or write a token file and MUST refuse to start with an error that names `FILESQUID_ADMIN_TOKEN`. On Unix the server MUST open the token file once with `O_NOFOLLOW` and `O_NONBLOCK` (so neither a symbolic link nor a FIFO can redirect or hang the open) and MUST refuse it unless that handle is a regular file owned by the server user with no group or other permission bits; the error MUST name the remedy for that case and MUST NOT contain the token. A first start MUST create the file atomically (`create_new`) and MUST remove a partly written file when the write or sync fails. A blank, owner-only, regular file (left by a crashed first start) MUST be replaced atomically, through a temporary file with a random name that is renamed over it, after a bounded wait of at most 50 rereads 20 ms apart (1 s) for a concurrent writer. Startup MUST NOT delete temporary token files, because one may belong to a concurrent server's recovery; an orphan left by a crash MUST NOT block a later recovery. | [F-056](../../../../../resources/prd.md#f-056-single-filesquid-api), [SRS-F-056](../../../../../resources/srs.md#srs-f-056-single-filesquid-api), [F-057](../../../../../resources/prd.md#f-057-desktop-and-server-hosts), [F-034](../../../../../resources/prd.md#f-034-family-accounts-and-shared-libraries), FileSquid [U-06](../../../../../resources/product-vision.md#platform-ownership-and-access), [U-18](../../../../../resources/product-vision.md#one-api-hosts-and-distributions), [T-053](../../../../../resources/product-vision.md#api-and-hosts) |

| API-S-018 Media elements (`<img>`, `<video>`, `<audio>`, `<source>`), which cannot send `Authorization`, MUST read file bytes through content handles ([ADR 030](../../../../../resources/architecture/030-filesquid-api-and-transports.md) Decision 5). **Minting:** `POST /api/v1/content-handles` MUST require a Bearer credential, MUST name exactly one file object, OCFL version and logical path, and MUST be authorised exactly like the ranged content read of that file version (same action, same resource, deny-by-default per API-S-004; a refusal is the refusal that read would get); a content handle MUST NOT mint another. The answer MUST carry the handle, its relative URL `/api/v1/content/<handle>` and its absolute expiry (RFC 3339 UTC). **Handle:** 256 bits from the operating system's CSPRNG (never fewer than 128), written as 43 base64url characters without padding, not derived from any token, key or file property; the API MUST keep only its SHA-256 digest, in memory only, and MUST NOT persist it. **Content route:** `GET` and `HEAD /api/v1/content/<handle>` MUST be served by the router on every host (desktop scheme and `filesquid-server`), with the handle as its only credential; it MUST serve only the bytes of the file version the handle names, with the same single-range handling and caps as the ranged content read (`206` and `Content-Range` for a satisfiable range; `416` and `Content-Range: bytes */<length>` for an unsatisfiable one; at most 16 MiB per answer through the desktop scheme, DE-S-005), and MUST grant no other file, version, route or method. **Expiry:** a handle MUST be refused once 300 seconds have passed since its mint or its last accepted request start, or 3,600 seconds since its mint, whichever comes first; expiry MUST be checked only when a request starts, and a response that has started MUST NOT be cut off. **Invalidation:** a handle MUST stop working when the credential that minted it ends (desktop relaunch; server token rotation, logout, session end or restart), and on `filesquid-server` the policy MUST be evaluated again at every request start. **Bound:** at most 1,024 live handles per issuing credential; minting another MUST evict that credential's least recently used handle, and expired handles MUST be removed when minting. **Denial:** an unknown, malformed, expired, evicted or revoked handle, or one whose policy check fails, MUST get one identical answer: `ApiError` `forbidden` (403) with `reason` `invalid_credentials`, not retryable, never 401 or 404, with identical status, headers and `ApiError` fields (every `GET` denial MUST carry the same body; a `HEAD` denial MUST carry the same status and headers with an empty body); the API MUST NOT read any file before the handle is accepted. This denial MUST cover every request whose path starts with `/api/v1/content/`, whether the handle is malformed, missing (an empty or extra path segment), unknown, expired, evicted or revoked: such a request MUST NOT fall through to the router's 404 or 405 fallback or to the authenticated-only `401 unauthorized` answer of API-S-004. **Redaction:** a handle MUST NOT be logged, journaled, echoed in an error, used as a metric label or rendered; a host that records request paths MUST record the template `/api/v1/content/{handle}`; minting is journaled per API-S-017, and every journal event that concerns a handle MUST have a redaction test. **Headers:** every content route answer, denials included, MUST carry `Referrer-Policy: no-referrer`, `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`; a success MUST also carry `Accept-Ranges: bytes` and the file's stored media type. The contract MUST document the handle as the content route's credential; the route MUST NOT declare the `public` action of API-S-015. | [F-056](../../../../../resources/prd.md#f-056-single-filesquid-api), [SRS-F-056](../../../../../resources/srs.md#srs-f-056-single-filesquid-api), [F-057](../../../../../resources/prd.md#f-057-desktop-and-server-hosts), FileSquid [U-11](../../../../../resources/product-vision.md#platform-ownership-and-access), [U-18](../../../../../resources/product-vision.md#one-api-hosts-and-distributions), [T-050](../../../../../resources/product-vision.md#api-and-hosts), [ADR 030](../../../../../resources/architecture/030-filesquid-api-and-transports.md) |
