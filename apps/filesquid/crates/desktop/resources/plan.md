# Implementation Plan: desktop (`filesquid-desktop`, Tauri 2)

Thin Tauri **host** for FileSquid and every distribution. It serves the `filesquid-api` router in-process through a Tauri custom URI scheme (`filesquid://localhost/api/...`; `http://filesquid.localhost/api/...` on Windows) with no TCP port, binds the API event channel, and owns capabilities, OS integration and the WebdriverIO packaged-window tests ([ADR 002](../../../../../resources/architecture/002-tauri2-desktop-shell.md), amended by [ADR 030](../../../../../resources/architecture/030-filesquid-api-and-transports.md)). Native processing (SQLite storage, OCFL coordinator, libvips/FFmpeg workers, OS adapters) belongs in the native-processing library `filesquid-native` at `apps/filesquid/crates/native` (name confirmed by the owner 2026-10-18; was `imagesquid_native`; created by [CL-0.1](../../api/resources/plan.md) with the SQLite journal store, the data-directory checks and `HostMonitor`, which this host links; grown by [DE-0.8](#phase-f0-catalog-jobs-ocfl-coordinator-global-task-05)). Catalog, search, replica and application-profile **meaning** belongs in `filesquid-api`. The webview gets opaque handles and API responses, never arbitrary filesystem paths or SQL. One binary serves every distribution through a Tauri config overlay. Cargo commands run from `apps/filesquid/` with `-p filesquid-desktop`. Do not Dockerize this host. Global sequence: [implementation-plan.md](../../../../../resources/implementation-plan.md).

`health_ping` is replaced by the API route. Packaged windows use ADR 017 WebdriverIO/Tauri-service; Playwright preview cannot prove the custom URI scheme or native capabilities.

Logs: stdout JSON ([DE-S-003](./srs.md)). Default: checkpoint-on-quit. `bundle.active` stays false until ADR 011 legal review ([ADR 020](../../../../../resources/architecture/020-distribution-web-and-tauri.md)).
