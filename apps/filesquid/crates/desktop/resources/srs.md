# Desktop SRS (scaffold)

`filesquid-desktop`, the Tauri 2 host for FileSquid and its distributions. Native file access stays out of the webview. Parent: [SRS-F-057](../../../../../resources/srs.md#srs-f-057-desktop-and-server-hosts).

| Local requirement | Parent |
|---|---|
| DE-S-001 The desktop serves the FileSquid API in-process through a Tauri custom URI scheme with no TCP listener (the API health route replaces `health_ping`). Any remaining Tauri command MUST be typed and explicitly authorized by a deny-by-default Tauri capability. | [PRD F-037](../../../../../resources/prd.md#f-037-setup-updates-and-diagnostics), [FE-064](../../../../../resources/product-vision.md#desktop-host-isolation) |
| DE-S-002 Capabilities are deny-by-default; no fs/shell/sql plugins at scaffold. The webview's Tauri capabilities MUST grant the main window only `core:event:allow-listen` and `core:event:allow-unlisten`; they MUST NOT grant any permission of the fs, shell, sql, dialog, http, process or opener plugins, `core:path` (which returns filesystem paths), the asset protocol, remote pages, webview labels or windows other than `main`. Filesystem and SQLite access stay in the Rust host behind the API authoriser. The native folder dialog of DE-S-017 MUST be shown by the Rust host through the `rfd` crate, which is not a Tauri plugin, and MUST NOT add a capability, a permission or a `#[tauri::command]`. The host MUST declare an app ACL manifest so Tauri refuses every custom command that no capability grants, and the build MUST fail when a capability file, the effective Tauri configuration (base, platform file and CLI overlay merged; it MUST create no window other than `main`), the crate manifest, a linked non-core Tauri plugin (outside test-instrumented builds' WebDriver plugin), the app ACL file or a `#[tauri::command]` breaks this policy. The host MUST register Tauri's `ipc` URI scheme itself and MUST refuse, before Tauri sees it, every IPC call on that scheme (the path Tauri's IPC script uses) whose method is not `POST`, whose page origin is not one of the app's own origins, whose invoke key is wrong or missing, or whose command is not `plugin:event|listen` or `plugin:event|unlisten`; it MUST hand allowed calls to Tauri's own access control and MUST journal Tauri's refusal of one, and a call Tauri never answers, as refusals. Calls on Tauri's `postMessage` path do not pass the host first; Tauri's own access control and invoke-key check decide them, and the host MUST journal their refusals from Tauri's trace (DE-S-003). The host MUST build its windows itself and MUST refuse every new-window request, every permission request and every download other than a `blob:` URL of an app page. | [PRD F-037](../../../../../resources/prd.md#f-037-setup-updates-and-diagnostics), [ADR 002](../../../../../resources/architecture/002-tauri2-desktop-shell.md) |

The library itself MUST live in the folder the owner chose for it (DE-S-018), which holds only its OCFL storage root; the data directory MUST NOT hold a library's OCFL storage root, originals or metadata records, and the host MUST NOT create a library anywhere but in an owner-chosen folder (owner decisions 2026-10-22, "Folders only" and "App data directory", [ADR 041](../../../../../resources/architecture/041-owner-folder-libraries-and-home-collections.md)). They are completely deleted from library and filesystem after recently deleted retention period expires."), the library's own retention period cached from its collection snapshot, operation receipts and pending intent, under a schema version (`PRAGMA user_version`) that is migrated forward and refused when newer than the host. It MUST implement the `filesquid-api` library catalog port without adding meaning: a stored receipt of the operation ID (in any library) answers first, then the create or revision rule, then every change, the revision, the receipt, the removal of the operation's pending intent and the journal entry in one transaction, and a failure MUST leave the catalog unchanged (a failed create leaves no file). A commit with no change MUST store nothing but the removal of its pending intent: no receipt, no journal entry and no new revision (API-S-019, owner decision 2026-10-19); an index refresh (`index_files`, `index_folders`) that changes nothing MUST likewise store no journal entry (DE-S-010). The journal entry MUST reach the host's activity journal; one the journal store refuses MUST be kept and forwarded later, never dropped. The catalog is a rebuildable index of the OCFL objects in the library folder, never the only copy: a catalog that is missing, belongs to another copy of the folder or does not match the snapshot head MUST be rebuilt from the folder when the library is opened (DE-S-010), so a moved or copied library folder reopens with its collections, folders and files; a copy keeps its library UUID, so opening a second folder with the UUID of a library that is already open MUST be refused (`library_already_open`) and two folders never share one index; a consistent backup MUST use SQLite's `VACUUM INTO` and be journaled, and a copy of the live file is not a supported backup. | DE-S-010 Every library change MUST follow ADR 005's sequence: the intent (operation ID, operation, expected revision) MUST be durable in the library's catalog before any OCFL byte; the changes MUST be applied in an open SQLite transaction and the entities they touched published as one collection-snapshot version (API-S-026) in the library's OCFL storage root, the owner-chosen library folder (DE-S-018; its staging and leases in `<data dir>/libraries/<library-id>.work/`, outside the root); only then MAY the catalog store the revision, the published snapshot version, the receipt, the journal entry and the intent's removal and commit. A failure known to publish nothing MUST discard the intent (if that removal itself fails, the intent stays pending and the failure is logged) and leave the catalog and head unchanged; a crash before the version is published MUST leave the intent pending with the head unchanged, and a retry under the same operation ID MUST complete once. At open, every library the host opens MUST be reconciled with its snapshot head in one journaled transaction (`library.reconcile`): a catalog that does not reflect the head, or is missing, MUST be rebuilt from it, every file entity with its home collection, logical path and file object identifier (API-S-026); a file object that the snapshot does not register MUST be counted in the reconcile's journal entry and left unregistered, never placed in a collection the owner did not choose ([ADR 041](../../../../../resources/architecture/041-owner-folder-libraries-and-home-collections.md)); receipts of every published operation MUST be restored from the version messages; intents of published operations MUST be cleared. A crash after publication MUST NOT lose acknowledged state. A W010 head MUST be refused and never repaired implicitly; writer fencing stays the engine's lease (OCFL-S-018, including its named gap). Index writes (`index_files`, `index_folders`) MUST publish their entities the same way and journal their entry with the version; an index refresh that changes nothing MUST write no version and no journal entry (owner decision 2026-10-19). An index refresh that fails MUST be journaled as `failed` with its error code, targeting only the library: once its own transaction has rolled back, the entry goes to the library's journal outbox in a transaction of its own, or, when the library is not open (no outbox), through the host's bounded journal queue, which never drops an entry. This `failed` entry is the only thing a failed refresh adds to the catalog, and the rule above that a failure leaves the catalog unchanged and stores the journal entry only after publication applies to the refresh's own transaction. A failure after the version is published leaves the catalog behind its head until reconcile at the next open. Before publishing, a library's snapshot MUST be refused above 1,000,000 entities. A snapshot that names another library, or holds an entity of another library, MUST NOT be loaded. A catalog whose OCFL root has lost its snapshot MUST publish every entity again at its next commit. A library's work directory that is a symbolic link or resolves outside the catalog directory MUST be refused, and its storage root MUST be the canonical owner-chosen folder (DE-S-018). Owner decisions (2026-10-19): a command or catalog index refresh that succeeds without a change MUST publish no version and MUST store no receipt and no journal entry (API-S-019); a retry of such a command is planned again and answers `conflict` or the same no-op. A refused or failed one is still journaled as `failed`. | [PRD NFR-001](../../../../../resources/prd.md#nfr-001-preservation-and-transactional-integrity), [PRD F-042](../../../../../resources/prd.md#f-042-ocfl-preservation-and-portable-recovery), [ADR 005](../../../../../resources/architecture/005-sqlite-local-postgres-hosted.md), [ADR 016](../../../../../resources/architecture/016-rust-ocfl-library.md), [ADR 041](../../../../../resources/architecture/041-owner-folder-libraries-and-home-collections.md) |

| DE-S-018 Library routes over owner-chosen folders. The host MUST serve the API-S-025 library and repair routes through `filesquid-api`'s library commands, injecting only where storage roots come from and the repair ledger: each folder the owner chose MUST be registered under an opaque location ID (`loc-` and at most 128 bytes) that names no path, resolved once to its canonical folder (never a symbolic link), with its storage backend and fenced version leases in the data directory, and one folder registered twice MUST share one backend and one set of leases; `overlaps` MUST answer true for nested, identical or unknown locations. The repair ledger MUST be persistent, in the operational store next to the activity journal: the consent entry journaled and recorded in one transaction before any object is repaired, and each object's outcome entry journaled with its receipt in one transaction or neither. The only principal allowed to repair is the desktop owner, the holder of the per-launch token. Each library a create or open binds MUST be served from the same root and leases by the file routes, scheduled for OCFL validation and listed for the API-S-029 history and backfill (DE-S-011). The owner picks each folder through the folder choice of DE-S-017; the owner-chosen folders MUST NOT reach the webview as paths (DE-S-006).
