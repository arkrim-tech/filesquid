filesquid-c2pa component diagram

C2PA module of FileSquid · apps/filesquid/crates/c2pa · drawn against the code on filesquid-product · 2026-10-15

filesquid-c2pa is the c2pa module of FileSquid (renamed from filesquid-provenance, ADR 029): an engine that reads, validates, mints, edits and embeds Content Credentials, implemented from scratch in Rust and still publishable on its own (ADR 026). FileSquid UIs reach it only through the one FileSquid API (filesquid-api, ADR 030), served by the filesquid-desktop and filesquid-server hosts. The crate is a workspace member. CP-0.1 built its foundation: the byte source and sink, fetcher and crypto-backend traits with the default RustCrypto backend, isolation tests, the wasm32 build check and the c2patool oracle harness. CP-0.2 built the JUMBF parser and the manifest store model with its bounded CBOR decoder, reading a store from a byte source (a sidecar .c2pa file) or by remote reference through the caller's fetcher. CP-0.3 built the format-handler interface with the JPEG (APP11) and PNG (caBX) handlers, reading a store embedded in an asset, and hard-binding validation (data hash, box hash and BMFF hash, with exclusion ranges); other formats are reported as unsupported. The other C2PA components in the diagram below (signature, certificate and timestamp validation, report, minting, embedding, surfaces) do not exist yet. The other C2PA code in the repository is the portable record types in filesquid-core (provenance.rs).
