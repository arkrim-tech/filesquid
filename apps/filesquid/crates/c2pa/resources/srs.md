# filesquid-c2pa SRS (planned)

The `c2pa` module of FileSquid. Parent: [SRS-F-054](../../../../../resources/srs.md#srs-f-054-c2pa-module).

| Local requirement | Parent |
|---|---|
| C2PA-S-001 The crate MUST read manifest stores embedded in assets, in sidecar `.c2pa` files and by remote reference, parsing JUMBF boxes and CBOR claims and assertions. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [C-054](../../../../../resources/product-vision.md#module-rules) |
| C2PA-S-002 The crate MUST validate hard bindings, COSE_Sign1 claim signatures, certificate chains against caller-supplied trust lists, RFC 3161 timestamps, available revocation status and ingredient chains, and MUST report the specification's validation status codes. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module) |
| C2PA-S-003 The crate MUST mint manifests and sign them only through a caller-supplied `Signer`. It MUST NOT operate or imply a certificate authority. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [ADR 015](../../../../../resources/architecture/015-prov-o-jsonld-and-c2pa-sdk.md) |
| C2PA-S-004 Edits MUST create new manifests referencing the prior asset as a parent ingredient. A signed manifest MUST NOT be modified in place. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [PRD F-043](../../../../../resources/prd.md#f-043-import-time-c2pa-records-and-action-disclosure) |
| C2PA-S-005 Format support MUST go through a format-handler interface. Unsupported formats MUST be reported as unsupported. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module) |
| C2PA-S-006 Cryptographic primitives MUST come from established crates behind a crypto-backend trait and MUST NOT be hand-rolled. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [SRS-F-054](../../../../../resources/srs.md#srs-f-054-c2pa-module), [C-054](../../../../../resources/product-vision.md#module-rules), [ADR 026](../../../../../resources/architecture/026-filesquid-provenance-engine.md) |
| C2PA-S-007 The official `c2pa` crate, `c2patool` and C2PA conformance files MUST verify interoperability in CI and MUST NOT be runtime dependencies. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [SRS-F-054](../../../../../resources/srs.md#srs-f-054-c2pa-module), [C-054](../../../../../resources/product-vision.md#module-rules) |
| C2PA-S-008 Default dependencies MUST exclude `filesquid-ocfl`, `filesquid-core` and every other FileSquid crate, Axum, Tauri, SQLite, libvips, FFmpeg and distribution code. The core MUST read and write through caller-supplied async byte sources and sinks and MUST NOT call `std::fs` or a network client directly. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [SRS-F-054](../../../../../resources/srs.md#srs-f-054-c2pa-module), [C-054](../../../../../resources/product-vision.md#module-rules), [FileSquid U-67](../../../../../resources/product-vision.md#c2pa-module) |
| C2PA-S-009 The crate MUST build for `wasm32-unknown-unknown` and MUST NOT require a server. Any developer MAY embed it wherever Rust runs. In FileSquid it runs behind `filesquid-api` in the desktop host, in `filesquid-server` and in the encrypted browser host, and MUST NOT be linked into the ciphertext-only hosted service. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [SRS-F-054](../../../../../resources/srs.md#srs-f-054-c2pa-module), [ADR 025](../../../../../resources/architecture/025-client-side-filesquid-engines.md), [ADR 026](../../../../../resources/architecture/026-filesquid-provenance-engine.md), [ADR 032](../../../../../resources/architecture/032-hosting-and-privacy-model.md) |
| C2PA-S-010 The crate MUST provide the command logic for `fsquid` (`read`, `verify`, `sign`, `edit`, `embed`, `report`), routed by `filesquid-cli`, and ships no binary of its own ([ADR 036](../../../../../resources/architecture/036-single-fsquid-cli.md)). It MUST build, test and publish on its own (per-crate repository extraction is superseded). | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [SRS-F-054](../../../../../resources/srs.md#srs-f-054-c2pa-module), [FileSquid U-67](../../../../../resources/product-vision.md#c2pa-module), [FE-072](../../../../../resources/product-vision.md#independent-library) |
| C2PA-S-011 PROV-O JSON-LD projection MUST be an optional, default-off feature. | [PRD F-054](../../../../../resources/prd.md#f-054-c2pa-module), [SRS-F-054](../../../../../resources/srs.md#srs-f-054-c2pa-module), [PRD F-043](../../../../../resources/prd.md#f-043-import-time-c2pa-records-and-action-disclosure), [ADR 015](../../../../../resources/architecture/015-prov-o-jsonld-and-c2pa-sdk.md) |
| C2PA-S-012 FileSquid MUST provide a presentation-only Content Credentials panel (manifest, signer, assertions, ingredients, validation status codes; unsigned, signed, invalid and unavailable distinct) as the vanilla TypeScript custom element `<fs-credentials-panel>` in `@filesquid/ui`, fed by the API's credentials routes and mountable in the default browser's sidebar slot or any distribution's view without depending on another panel. | [F-055](../../../../../resources/prd.md#f-055-default-ui-and-panel-composition), [SRS-F-055](../../../../../resources/srs.md#srs-f-055-default-ui-and-panel-composition), [ADR 028](../../../../../resources/architecture/028-filesquid-ui-packages-and-panel-composition.md), [ADR 031](../../../../../resources/architecture/031-vanilla-typescript-ui-and-white-label-theming.md) |
