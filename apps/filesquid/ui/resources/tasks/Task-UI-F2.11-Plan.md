## Contract (openapi.json 0.28.0, nothing assumed)

| Need | Route | Notes |
|---|---|---|
| List, current, size | `GET /files/history`, `GET /files/versions`, `GET /files/history-size` | already used by UI-F2.3 |
| Restore | `POST /files/restorations` command | already used; keeps the command envelope (API-F2.13) |
| Edit label | `PUT /files/labels` command `{ envelope, input: { library_id, object_id, version, label } }` | label 1 to 512 UTF-8 bytes, not blank, no control characters; `null` or absent clears it; commits one version (kind `label`); expected revision is the object's head as read; a label that would not change what the version shows is refused 409; stale head is `conflict` 409; at most 1,000 labelled versions per object |
| Download | `GET /files/download?library_id&object_id&version&path` | whole file as attachment, journaled as `file.download`; through the desktop scheme every answer is capped at 16 MiB (DE-S-005), so larger files use ranged `GET /files/content` reads of at most 8 MiB |
| Storage used (library) | `GET /files/library-history-size` | history bytes only; no route reports a library's used bytes or free disk space (API-S-038 is not delivered), see Owner decision below |

## Design

1. **Row menu** (`fs-versions-panel`): items **Restore as new version** (not on the current version, not on a removal), **Download this version** (not on a removal: it holds no file), **Edit label** (every row). The current version now has a menu too (Download, Edit label); it keeps its Current chip, which sits before the menu button. Arrow keys, Escape and Tab behave as UI-F2.3 built them.
2. **Edit label** is a command through `FileSource.setVersionLabel(object, version, label | null, { revision })` over `PUT /files/labels`, expected revision the head as last read. A small modal dialog (`version-label-dialog.ts`, same shell as the restore dialog): title "Edit label for {version}", the label field prefilled with the current label, a help line, Cancel and **Save** (the one filled primary). Blank input clears the label (sent as `null`). An unchanged label closes the dialog without a call (the route would refuse it 409). The label is checked as the route does (`labelProblem`) before sending; a refusal (stale head `conflict`, 503, offline) stays in the dialog with `failureText`. On success the panel emits `fs-files-change` (`operation: "label"`) and reloads the rows; the polite status announces "Label of {version} saved." or "Label of {version} removed.".
3. **Download** through `DownloadSource.readVersionFile(file, { signal })` (`src/files/download-source.ts`, `ClientDownloadSource` over `FileSquidClient.request` and `.read`): the file's size from `GET /files/details`; up to 16 MiB through `GET /files/download` (journaled by the API); larger through ranged `GET /files/content` reads of at most 8 MiB, at most 4,096 reads (32 GiB), so the loop is bounded and a file beyond the bound is refused with a message instead of looping. The result is a `Blob`; `saveFileToDevice(blob, name)` (`src/components/save-file.ts`, side effect named in its name) hands it to the browser through an object URL that is revoked after the click. The file keeps its display name. While it runs the row's menu button is busy and the status region says "Downloading {version} of {name}…"; a failure shows a visible alert line "Could not download {version}. Nothing was changed." with the reason.
4. **History size**: per file in File info as a new **History size** row ("{size} · {count} versions", mono no) after the Size row, from `GET /files/history-size` (a failed read leaves the row out, as the Versions eyebrow leaves the size out); the Versions eyebrow keeps its size. Per library: see Owner decision.
5. **Labels** (default and ImageSquid tables, `REQUIRED_LABEL_KEYS`): `versionsDownloadAction` "Download this version", `versionsEditLabelAction` "Edit label", `versionsEditLabelTitle` "Edit label for {version}", `versionsEditLabelField` "Label", `versionsEditLabelHelp` "Leave it empty to remove the label.", `versionsEditLabelSave` "Save", `versionsLabelSaved` "Label of {version} saved.", `versionsLabelCleared` "Label of {version} removed.", `versionsDownloading` "Downloading {version} of {name}…", `versionsDownloadFailed` "Could not download {version}. Nothing was changed.", `versionsDownloadTooLarge` "This version is too large to download here.", `filePanelHistorySize` "History size", `filePanelHistorySizeValue` "{size} · {versions}". The first two are the strings of mockup 26; the rest are proposed here and approved by owner answer 13 only if the owner accepts them (flagged in the hand-back).
6. `MemoryFileSource` gains `setVersionLabel` and `readVersionFile` so tests and demos run without the API; the Playwright fake serves `PUT /files/labels` and `GET /files/download`.

## Owner decision for the hand-back

"History size shown in storage used": the shell's Storage used block (`StorageSummary`: used, history, free bytes) needs a library's used bytes and the host disk's free bytes. `GET /files/library-history-size` supplies only the history part, and no route in the 0.28.0 contract supplies used or free bytes (API-S-038, already deferred by UI-F2.18). Nothing is stubbed: the block stays as UI-F2.18 left it until the platform engineer delivers those facts, and `library-history-size` then supplies `historyBytes`.
