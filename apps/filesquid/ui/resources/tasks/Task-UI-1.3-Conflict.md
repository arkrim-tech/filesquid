# Task UI-1.3 Conflict Artifact: what first use asks of the API and the API does not offer

Raised while executing [Task UI-1.3](../plan.md) under [sync-logic.md](../../../../../.agents/rules/sync-logic.md). The task could not stop at the first of these: the other parts of the row (recent libraries, the library facts and the rebuild job) are unaffected and are done. Each conflict below is built behind one named seam, so the owner's resolution is a small edit; nothing here changes a requirement document.

## Conflict 1: the Location row of the first-use dialog against the location-choices answer

1. **Conflict description.** Mockup 57 and [UI-S-034](../srs.md) draw the chosen folder "by name and volume" ("{folder} · on {volume}"). [API-S-034](../../../crates/api/resources/srs.md) answers the folder choice with an opaque location ID only and forbids a folder name in the request and the answer. The UI cannot show what the API will not tell it.
2. **PRD/SRS reference.** UI-S-034: "**Location** showing the chosen folder by name and volume, '{folder} · on {volume}', with **Choose folder…** (secondary), which opens the native folder dialog through the location-choices route (API-S-034, purpose `create`); 'The folder must be empty. FileSquid never shows its path.'"
3. **ADR reference.** API-S-034: "The request and the answer MUST NOT carry a filesystem path, storage key or folder name, and a refusal or a journal entry MUST NOT name one (API-S-005)." The owner's approved strings of owner answer 13 do not list "{folder} · on {volume}".
4. **Recommended resolution.** Either (a) the owner allows the host to answer a display name and volume name beside the location ID, a change to API-S-034, API-S-005 and the contract (then `parseLocationChoice` and `<fs-first-use>` show `libraryFolderChosen` as "{folder} · on {volume}"), or (b) UI-S-034 and mockup 57 drop the folder and volume and say only that a folder is chosen. Built meanwhile: option (b), with `libraryFolderNone` "No folder chosen yet" and `libraryFolderChosen` "Folder chosen" (proposed strings). Artifacts to update for (a): `resources/ui-mockups/v3/57-first-use-library.svg` (unchanged), UI-S-034, API-S-034, API-S-005, `crates/api/openapi.json` and `ui/src/api/schema.d.ts`; for (b): UI-S-034 and mockup 57.
5. **Impact assessment.** Nothing breaks: the dialog works either way. With (b) the owner cannot see which folder they chose, only that one is chosen, so choosing the wrong empty folder is possible before Create.

## Conflict 2: "creates the library, then its first collection (API-S-019)" against the routes that exist

1. **Conflict description.** UI-S-034 and the Agent Prompt create the first collection through the library commands of API-S-019, and the plan row says no part of the row is blocked. The library domain commands, `CreateCollection` among them, exist in `filesquid-api` ([CL-0.2](../../../crates/api/resources/plan.md) "adds no route"), but no HTTP route or Tauri command exposes them: `GET /api/v1/openapi.json` has no collection route.
2. **PRD/SRS reference.** UI-S-034: "**Create library** (primary), which creates the library, then its first collection (API-S-019), each journaled; a failure after the library exists MUST keep the library and show the error with Try again for the collection." UI-1.3 plan row: "no part of this row is blocked."
3. **ADR reference.** [ADR 041](../../../../../resources/architecture/041-owner-folder-libraries-and-home-collections.md) Decision 4: every write names a destination collection, so a library with no collection cannot take an upload; Decision 9 creates "untitled collection" only for a restore.
4. **Recommended resolution.** Add one API task (platform engineer) for a command route in the style of rename and rebuild: `POST /api/v1/libraries/collections`, a `CommandEnvelope` with scope `library:<library_id>` and the library's current revision, input `{ library_id, title }`, committed result `{ collection_id, title }`, journaled as `library.collection.create`, plus the contract and `schema.d.ts`; the same route serves the New menu's collection creation. Built meanwhile: `ClientLibrarySource.createCollection` sends exactly that command and checks its answer (`parseCollection`); against a host without the route (404 or 405) first use ends on its Try again state with the library kept. Artifacts to update: the API plan and SRS (new row, API-S-019), `crates/api/openapi.json`, `ui/src/api/schema.d.ts`, the global plan's Task 1.2 or FS-2.5 dispatch list.
5. **Impact assessment.** Until the route exists the first run of the desktop app creates the library and then shows a failed collection step; the owner has a library with no collection, and UI-1.2's destination picker offers nothing to upload into.

## Conflict 3: rows the SRS places on the library page that the API cannot fill

1. **Conflict description.** UI-S-027 lists the library page's **Storage used** ("{size}, including {history} of version history", `libraryFactStorage`) and **STORAGE BY COLLECTION** (owner answer 16, "Yes"). The API's `GET /api/v1/files/library-history-size` gives one total with the history included and no split, and `GET /api/v1/files/collection-history-size` needs a `collection_id` that no navigation handle gives the UI (handles are opaque and must not be parsed). The strings of these rows are not in this task's approved list (owner answer 13 as the Agent Prompt copies it).
2. **PRD/SRS reference.** UI-S-027: "Storage used '{size}, including {history} of version history' (`libraryFactStorage` (new))" and "the eyebrow STORAGE BY COLLECTION (on this page: owner answer 16, verbatim: 'Yes') with one row per collection and its size right-aligned".
3. **ADR reference.** [storage-route.ts](../../src/app/storage-route.ts) records the same gap for the sidebar: "does not split the history out of the total, so the 'incl. {history} history' caption is left out rather than guessed."
4. **Recommended resolution.** Platform engineer: add the history bytes beside the total on the library-history-size answer, and a collection ID on the navigation collection node (or a per-library storage-by-collection route). Then a UI task adds the two rows. Not built here, and not stubbed.
5. **Impact assessment.** The library page shows ID, format, objects and Free space; the sidebar block keeps its total and free space without the history caption. No wrong figure is shown.
