# `@filesquid/ui` SRS (scaffold)

FileSquid's default distribution and component library. Parents: [SRS-F-062](../../../../resources/srs.md#srs-f-062-drive-style-views-sorting-selection-and-layout-preferences)–[SRS-F-066](../../../../resources/srs.md#srs-f-066-file-and-folder-sharing-roles-links-and-shares-view) (UI-S-006–010), [SRS-F-055](../../../../resources/srs.md#srs-f-055-default-ui-and-panel-composition), [SRS-F-058](../../../../resources/srs.md#srs-f-058-white-label-distributions), [SRS-UI-007](../../../../resources/srs.md#srs-ui-007-light-and-dark-themes). UI-S-014 (client authorisation) traces to [SRS-F-056](../../../../resources/srs.md#srs-f-056-single-filesquid-api), [API-S-004](../../crates/api/resources/srs.md) and, for content handles, [API-S-018](../../crates/api/resources/srs.md). UI-S-011, UI-S-012 and UI-S-013 moved here from the former `apps/frontend` SRS (now the ImageSquid SRS), where they were FE-S-001, FE-S-002 and FE-S-004.

| Local requirement | Parent |
| --- | --- |
| UI-S-011 The UI is a client-rendered vanilla TypeScript application built with Vite, using standard custom elements and no UI framework. Private data MUST NOT be server-rendered. | [PRD F-036](../../../../resources/prd.md#f-036-browser-and-mobile-web-experience), [FileSquid U-29](../../../../resources/product-vision.md#one-api-hosts-and-distributions), [ADR 031](../../../../resources/architecture/031-vanilla-typescript-ui-and-white-label-theming.md) |
| UI-S-012 The UI reaches FileSquid only through `FileSquidClient` (`request()`, `read()`, `command()`, `upload()`, `subscribe()`), which selects the HTTP-plus-event-channel adapter on `filesquid-server`, the custom-scheme adapter on `filesquid-desktop`, and later the browser-host adapter. The desktop base URL MUST be `filesquid://localhost` on macOS, iOS and Linux and `http://filesquid.localhost` on Windows and Android; desktop events MUST arrive as the Tauri event `filesquid-event`. Every command and upload MUST carry a `CommandEnvelope` (schema version 1, non-empty operation id, expected revision and scope); a 2xx answer MUST resolve to a `CommandOutcome` (`committed`, `pending`, `conflict` or `error`) for the same operation id, so `error` arrives only as a 2xx outcome body; HTTP 409 MUST resolve to `conflict`; any other non-2xx answer MUST reject with `ApiError`; only `committed` is completion evidence. Without a range, `read()` MUST send no `Range` header; with one, it MUST send an inclusive `Range: bytes=<start>-<end>`, or `Range: bytes=<start>-` when no end is given (start ≥ 0, end ≥ start), and MUST refuse an invalid range before sending. | [PRD F-037](../../../../resources/prd.md#f-037-setup-updates-and-diagnostics), [F-056](../../../../resources/prd.md#f-056-single-filesquid-api), [CORE-S-005](../../crates/core/resources/srs.md), [ADR 030](../../../../resources/architecture/030-filesquid-api-and-transports.md) |
| UI-S-013 UI tests run against production artifacts (`vite build` plus `vite preview`) with strict DOM assertions: custom elements defined, labels from the active label table, computed token values in light and dark, no console errors. | [PRD NFR-008](../../../../resources/prd.md#nfr-008-maintainability-and-verified-engineering), [SRS-NFR-008](../../../../resources/srs.md#srs-nfr-008-maintainability-and-verified-engineering), AGENTS.md UI Test Mandate, [ADR 017](../../../../resources/architecture/017-test-runners-and-reporting.md) |
| UI-S-014 When a token is known, `FileSquidClient` MUST send `Authorization: Bearer <token>` on every HTTP request and MUST offer the subprotocols `filesquid.events.v1` then `filesquid.bearer.<token>` on the event channel WebSocket; with no token it sends no credential, so the API answers `missing_credentials`. The token MUST come from `window.__FILESQUID_LAUNCH_TOKEN__` on the desktop host and from the client's `token` option on `filesquid-server`; it MUST be held in memory only (no Web Storage, cookie or URL) and MUST NOT be logged, rendered or included in an error. A supplied token that is empty or outside the RFC 7230 `token` characters MUST be refused before sending (status 0, `invalid_credentials`). The client's typed error MUST carry the contract's `code`, `retryable` and `reason`, and the UI MUST show `missing_credentials`, `invalid_credentials` and `not_permitted` with their own labels. A content handle ([API-S-018](../../crates/api/resources/srs.md)) is not a token and is the only credential the UI MAY put in a URL: `FileSquidClient` MUST mint it with an authenticated request (`POST /api/v1/content-handles`) and return its URL on the active host's base; a view MAY use that URL only as the `src` of `<img>`, `<video>`, `<audio>` or `<source>`, and MUST NOT put it in the page address, history, Web Storage, a cookie, a log, rendered text, an error or a link that opens another window or tab. When a media element that uses a handle reports an error, the UI MUST mint a new handle at most once for that error and resume at the same position and paused state; if the new handle fails too, it MUST show the error. | [F-056](../../../../resources/prd.md#f-056-single-filesquid-api), [SRS-F-056](../../../../resources/srs.md#srs-f-056-single-filesquid-api), [API-S-004](../../crates/api/resources/srs.md), [API-S-018](../../crates/api/resources/srs.md), [ADR 030](../../../../resources/architecture/030-filesquid-api-and-transports.md) |
| UI-S-001 Components MUST be styled only through design tokens (CSS custom properties, light and dark) and worded only through a label table keyed by internal names (repository, library, collection, virtual collection, virtual exhibit, file). | [PRD F-055](../../../../resources/prd.md#f-055-default-ui-and-panel-composition), [SRS-F-055](../../../../resources/srs.md#srs-f-055-default-ui-and-panel-composition), [PRD F-058](../../../../resources/prd.md#f-058-white-label-distributions), [T-051](../../../../resources/product-vision.md#api-and-hosts), [FileSquid U-04](../../../../resources/product-vision.md#platform-ownership-and-access), [FileSquid U-24](../../../../resources/product-vision.md#one-api-hosts-and-distributions) |
| UI-S-002 The default UI MUST provide a Drive-style browser with navigation, breadcrumb, list and grid views, preview, upload, create folder, rename or move, remove and restore, and a sidebar with Details, Versions, Metadata, Content Credentials, Activity and Sharing panels in named slots. | [F-055](../../../../resources/prd.md#f-055-default-ui-and-panel-composition), [FileSquid U-01](../../../../resources/product-vision.md#platform-ownership-and-access) |
| UI-S-003 Panels MUST plug into named sidebar slots and MUST NOT depend on each other. Each file fact is shown by the panel of its owning module. | [PRD F-055](../../../../resources/prd.md#f-055-default-ui-and-panel-composition), [SRS-F-055](../../../../resources/srs.md#srs-f-055-default-ui-and-panel-composition), [C-055](../../../../resources/product-vision.md#module-rules), [FileSquid U-24](../../../../resources/product-vision.md#one-api-hosts-and-distributions) |
| UI-S-004 The UI MUST state which host it is connected to and who can read files there: the owner on their own device (desktop); the server's named operator and other users within their permissions (`filesquid-server`); or the owner in this browser only (encrypted browser host). It MUST show backup and sync to `*.filesquid.tech` separately from the connected host, as ciphertext only. Host type and operator name come from the API; the UI MUST NOT infer them. | [PRD F-057](../../../../resources/prd.md#f-057-desktop-and-server-hosts), [SRS-F-057](../../../../resources/srs.md#srs-f-057-desktop-and-server-hosts), [PRD F-059](../../../../resources/prd.md#f-059-hosted-encrypted-backup-and-sync-service), [FileSquid U-20](../../../../resources/product-vision.md#one-api-hosts-and-distributions), [ADR 032](../../../../resources/architecture/032-hosting-and-privacy-model.md) |
| UI-S-005 A distribution's label table MUST define every key of the default table, and its token file every default token; a unit test MUST fail otherwise. | [F-058](../../../../resources/prd.md#f-058-white-label-distributions), [SRS-UI-007](../../../../resources/srs.md#srs-ui-007-light-and-dark-themes) |
| UI-S-006 `<fs-file-browser>` MUST provide the sidebar views (home, all, personal, recent, favorites, shares, tags, deleted files) with a view filter field, storage-used indicator and settings; one New control (upload files, upload folder, new folder); list as default layout with checkbox, name, size and modified columns, per-row share and actions controls and a footer summary; column-header sort with reverse and a grid sort menu; row and header checkboxes with a bulk action bar that states the effective scope; the per-item and right-click menu (favorite, details, manage tags, rename, move or copy, download, share, delete; reveal in file manager on desktop); drag-to-folder move and a folder picker for move or copy; shared and link badges; preview-or-download on click; an optional hover card off on touch and under reduced motion; a start-view setting (home or personal library root); and persisted per-user preferences read through the API. | [PRD F-062](../../../../resources/prd.md#f-062-drive-style-views-sorting-selection-and-layout-preferences), [SRS-F-062](../../../../resources/srs.md#srs-f-062-drive-style-views-sorting-selection-and-layout-preferences) |
| UI-S-007 The global search bar MUST offer Type, People, Modified and Location chips with typed suggestions, chip-plus-text layering, per-chip remove and clear-all, drop-down results and Enter for the full list with column sorting; the sidebar filter MUST narrow the current view only; the active scope and result summary MUST show as chips; unsupported operators MUST be shown as unsupported. | [PRD F-063](../../../../resources/prd.md#f-063-file-search-query-language-and-filter-chips), [SRS-F-063](../../../../resources/srs.md#srs-f-063-file-search-query-language-and-filter-chips) |
| UI-S-008 `<fs-activity-panel>` MUST show per-file activity and comments with a comment box in a named sidebar slot, independent of other panels; an activity view reachable from the header MUST show the user stream with the filters all, by me, by others, file changes, favorites, shares, comments and tags, grouped by day with relative times. A **Publish to Bluesky** action on a public file or readable activity entry MUST open the outgoing-disclosure preview and publish only on explicit confirmation through the user's AT Protocol connection; no RSS or bearer-link feed MAY exist. | [PRD F-064](../../../../resources/prd.md#f-064-file-activity-comments-and-user-activity-stream), [SRS-F-064](../../../../resources/srs.md#srs-f-064-file-activity-comments-and-user-activity-stream) |
| UI-S-009 The Versions panel MUST list versions newest first with label, relative time and size, mark the current version, and offer restore, download and edit label per version. No delete, expiry or thinning control MAY appear. | [PRD F-065](../../../../resources/prd.md#f-065-file-version-history-and-retention), [SRS-F-065](../../../../resources/srs.md#srs-f-065-file-version-history-and-retention) |
| UI-S-010 `<fs-sharing-panel>` MUST show internal shares (people or teams picker, others with access, internal link) and external shares (public link with password and expiry, bearer-access disclosure) in a named sidebar slot, and MUST hide a control the server administrator disabled while saying so. | [PRD F-066](../../../../resources/prd.md#f-066-file-and-folder-sharing-roles-links-and-shares-view), [SRS-F-066](../../../../resources/srs.md#srs-f-066-file-and-folder-sharing-roles-links-and-shares-view) |
