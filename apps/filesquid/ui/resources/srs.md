# `@filesquid/ui` SRS (scaffold)

FileSquid's default distribution and component library. Parents: [SRS-F-062](../../../../resources/srs.md#srs-f-062-drive-style-views-sorting-selection-and-layout-preferences)–[SRS-F-066](../../../../resources/srs.md#srs-f-066-file-and-folder-sharing-roles-links-and-shares-view) (UI-S-006–010), [SRS-F-055](../../../../resources/srs.md#srs-f-055-default-ui-and-panel-composition), [SRS-F-058](../../../../resources/srs.md#srs-f-058-white-label-distributions), [SRS-UI-007](../../../../resources/srs.md#srs-ui-007-light-and-dark-themes). UI-S-015 (brand slots, theme control and contrast contract) traces to SRS-UI-007 and SRS-F-058. UI-S-016 (accessibility contracts) traces to [SRS-NFR-006](../../../../resources/srs.md#srs-nfr-006-accessibility-and-usability). UI-S-017 (navigation preferences) traces to [SRS-F-004](../../../../resources/srs.md#srs-f-004-collections-folders-and-navigation) and UI-S-018 (host privacy indicator data) to [SRS-F-057](../../../../resources/srs.md#srs-f-057-desktop-and-server-hosts) and [SRS-F-059](../../../../resources/srs.md#srs-f-059-hosted-encrypted-backup-and-sync-service). UI-S-014 (client authorisation) traces to [SRS-F-056](../../../../resources/srs.md#srs-f-056-single-filesquid-api), [API-S-004](../../crates/api/resources/srs.md) and, for content handles, [API-S-018](../../crates/api/resources/srs.md). UI-S-011, UI-S-012 and UI-S-013 moved here from the former `apps/frontend` SRS (now the ImageSquid SRS), where they were FE-S-001, FE-S-002 and FE-S-004.

| UI-S-014 When a token is known, `FileSquidClient` MUST send `Authorization: Bearer <token>` on every HTTP request and MUST offer the subprotocols `filesquid.events.v1` then `filesquid.bearer.<token>` on the event channel WebSocket; with no token it sends no credential, so the API answers `missing_credentials`. when a re-render or route change removes the focused element, focus MUST move to a defined target (route change: `main`; Monitor token form: the token field; Monitor alert: the alert; Monitor loaded: its first section heading); | UI-S-023 Client event delivery. The UI MUST forward its console warnings and errors to `POST /api/v1/client-events` (API-S-030) through a bounded in-page queue: it sends batches of at most 20 events and 16 KiB, at most 60 requests a minute, and after a `429`, a refused request or a network failure retries the same events with exponential backoff (from 1 second, doubling, at most 60 seconds between attempts, never sooner than `Retry-After`) for as long as the page is open. Rate limits MUST only delay events, never merge them: every event is sent on its own and becomes its own journal entry. Only the events still queued when the page closes MAY be counted, and the UI MUST then send one `ui.console.overflow` event with that count (a keep-alive request on `pagehide`); this is the one unavoidable gap recorded under the no-exemptions rule of `logging-enforce.md` (owner decision 2026-10-19). Events carry only the level, a fixed component identifier, an error code and opaque IDs, never message text, URLs, file names or stack traces. | [PRD F-061](../../../../resources/prd.md#f-061-activity-journal-and-live-health-monitoring), [SRS-F-061](../../../../resources/srs.md#srs-f-061-activity-journal-and-live-health-monitoring), [ADR 033](../../../../resources/architecture/033-activity-journal-and-live-health-monitoring.md) |
